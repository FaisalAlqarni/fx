# Codex agents are generated to disk; opencode agents are converted at runtime

`scripts/gen-codex-agents` writes one `<name>.toml` file per read only agent
into `codex/agents/`, each opening with a generated file header naming its
source (`scripts/gen-codex-agents`, `HEADER`: "generated by
scripts/gen-codex-agents from {source}: edit there, not here"). `codex/agents/`
is committed. `scripts/check-generated` regenerates every file into a scratch
directory and diffs it against what is committed, failing the gate on any
drift.

opencode has no equivalent committed artifact. `lib/agent-dialects.js`'s
`toOpencodeAgent` runs live, from two call sites: `plugins/fx.js:155`, inside
the config hook every opencode session runs, and
`scripts/fx-opencode-install:103`, the standalone installer's own converter
call. Both call the same function; there is no second implementation of the
opencode dialect, confirmed directly: `scripts/fx-opencode-install` requires
`lib/agent-dialects.js` for it rather than carrying its own conversion logic,
and this branch's own history records removing a Python `convert_agent`
duplicate in favour of exactly this, one JavaScript implementation called
from both paths.

The asymmetry follows from what each runtime needs an agent to be. Codex
reads a subagent's role from a file under `$CODEX_HOME/agents/` before any
hook runs in that session, so the role has to already be on disk, in Codex's
own TOML shape, before Codex starts. opencode takes its agents through the
config object fx's plugin hook returns on every session start; there is
nothing to write ahead of time, because the config call itself is the moment
opencode asks.

One source of truth, `agents/*.md`, and one converter per dialect, is the
rule underneath both sides. A hand edited `.toml` under `codex/agents/` is
caught by `scripts/check-generated` the next time the gate runs, the same way
a hand edited generated file is caught anywhere else in fx. A second Codex
converter, writing `.toml` files by some other path, would defeat that gate
entirely: two independently written outputs can each pass their own review
and still drift from each other silently, which is the exact failure a
single generator with a diffed gate exists to prevent.

## Consequences

- Codex gets a build step (`scripts/gen-codex-agents`, checked by
  `scripts/check-generated`); opencode gets neither, because a runtime
  converter has nothing to drift from between commits.
- Any change to what makes an agent read only, or to what an agent's body
  says, starts in `agents/*.md` and flows outward through exactly one path
  per runtime. Editing `codex/agents/*.toml` directly, or opencode's live
  agent object, is a local, unreviewed fork that the next generation or the
  next config call overwrites or ignores.
- A third runtime gets to choose disk artifact or runtime conversion on its
  own merits, decided by whether that runtime reads agent roles before or
  during the hook that would produce them, not copied from either existing
  choice.
