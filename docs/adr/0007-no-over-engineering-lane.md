# fx has no over-engineering lane; ponytail owns that intent

fx's README, INSTALL, SURFACE and marketplace description all claimed fx
replaces `ponytail`. **It never did.** ponytail is a substantial plugin with its
own hooks, an MCP server, a Gemini extension, an opencode config, six skills and
benchmarks, and fx absorbed none of it.

What was genuinely lost in consolidation is `ponytail-review`, a
forced-output-grammar lane for over-engineering only. fx has no equivalent, and
that is exactly the lane that would have caught fx over-engineering itself.

`PREAMBLE.md` carries a routing row naming ponytail as the owner, conditioned on
it being installed, and says plainly that fx has no lane for it.

## Consequences

- fx does the pipeline; ponytail does over-engineering; neither claims the
  other's job. Two plugins asserting one intent is a collision, and only one of
  them had a lane.
- The ladder text stays in `PREAMBLE.md`. It arrived from ponytail, is general
  guidance fx references throughout, and is injected rather than claimed as a
  lane, so it contests nothing.
