# On Codex, fx declares the model, and the preamble is rendered for how Codex loads a lane

Status: accepted, 2026-10-28.

Amends: 0020 (the premise that only names differ per runtime), 0039 (shell `apply_patch` stays the only shell write detection)

## Context

On Codex, two fields of a model's catalog entry decide whether the model gets Codex's skill trigger rules and whether it gets an `apply_patch` tool: `include_skills_usage_instructions` and `apply_patch_tool_type`. For every OpenRouter slug Codex 0.164.0 uses entries or fallback metadata with both off. ADR 0020 assumed only the lane names differ per runtime, and `codex.md` assumed every Codex model has `apply_patch`, so fx never declared either. Sonnet and GPT cope on the preamble alone; Haiku 4.5 does not. Measured baseline with fx 0.7.0 on Haiku: the lane was read first in 0 of 6 runs and code was written before a design in 4 of 6 (`docs/plans/2026-10-28-codex-model-catalog/research/codex-integration.md`, section 5).

## Decision

1. **fx-setup declares a third-party model to Codex** with a profile-scoped `model_catalog_json`. The entry starts from Codex's own entry for the slug and sets `include_skills_usage_instructions: true` and `apply_patch_tool_type: "freeform"`. fx writes `$CODEX_HOME/fx-<provider>.config.toml` and `fx-<provider>.catalog.json`, only when absent or carrying fx's marker, and never touches `config.toml`. The user runs `codex --profile fx-<provider>`.
   Evidence: `src/lib/codex-catalog.ts` `buildCatalog`, `setupCatalog`
2. **On Codex the preamble's ordering clause is a per-runtime slot, `{{ORDER}}`.** Codex renders it as: reading the lane's `SKILL.md` is the first file read, before any file in the repository, and the render names absolute lane paths. Claude Code, opencode and opencode-v2 renders are unchanged. Nothing sits above the opening imperative (ADR 0002). "Rendered, not copied" (ADR 0020) stands.
   Evidence: `src/lib/preamble.ts` `ADDRESSING`; `PREAMBLE.md`
3. **ADR 0039's shell `apply_patch` match stays** as the only shell write detection. It is the only write channel fx sees for providers that drop `custom` tools, and the fallback elsewhere. Heredoc writes stay unseen by decision, and no shell text parsing is added.
   Evidence: `src/hooks/fx-codex.ts` (the existing `apply_patch` shell match)
4. **The stated limit.** For Anthropic models on OpenRouter, OpenRouter drops the `custom` `apply_patch` tool (run `ap4-tools`), so fx's write checks see only shell-run `apply_patch`. Heredoc writes are not seen. Protection against code before a design there rests on Codex's skill contract plus the preamble. The owner accepted shipping with this limit on 2026-10-28. The fx-setup report and `references/harnesses/codex.md` state it.
   Evidence: `commands/fx-setup.md` (Codex section); `references/harnesses/codex.md` "Tool vocabulary"
5. **The conformance runner's Codex rows under OpenRouter run with the same profile and catalog a user gets**, generated by the same CLI, with `--profile fx-openrouter`.
   Evidence: `tests/conformance/lib/live.sh`

## Consequences

- Codex's trigger rules and fx's preamble land in the same message, so a model on a third-party provider gets a skill contract from the runtime.
- Under the profile, the catalog replaces the remote model list. Any other model run with `--profile fx-<provider>` falls back to Codex's fallback metadata, and the fx-setup report says so.
- OpenAI models on OpenRouter get an `apply_patch` tool (run `ap5-gpt-tools`), so fx's edit-tool path sees their writes. Anthropic models there do not.
- The 0020 premise that only names differ per runtime no longer holds on Codex. The rest of 0020 and of 0039 holds for other runtimes.
- Related: ADR 0016 (harness facts live in `references/harnesses/`), 0021 (the bootstrap invokes lanes, unchanged), 0022 (Codex declares), 0024 (fx says what it cannot observe).

## Alternatives

- **Put `model_catalog_json` at the top level of the user's `config.toml`.** Rejected: the file replaces the whole catalog (run `m1-top`: 1 model left), so every ChatGPT-login model in that home loses its bundled metadata, and fx-setup does not edit `config.toml`.
- **Re-deliver the preamble at UserPromptSubmit and lane-check shell redirects.** Rejected by the owner: it works around Codex instead of declaring the model, repeats the preamble every turn, and makes redirect parsing the main write channel.
