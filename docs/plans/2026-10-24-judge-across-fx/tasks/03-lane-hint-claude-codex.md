# 03: Lane hint on Claude Code and Codex

**Status:** ready-for-agent
**Blocked by:** 01, 02
**Phase:** MVP

**What to build:** on Claude Code and Codex, when the user sends a request and a judge is configured, fx asks the judge, in one request, what kind of work it is and whether it needs sources outside the repository; for a kind with several lanes (`build`, `review`, `writing`) a second request asks which lane; a confident answer adds one line to the model's context, `[fx] lane hint: <lane as this harness addresses it>`, and nothing reaches the user's terminal. Slash commands, text starting `[fx] `, fx's own Stop continuation, subagent prompts and prompts under three words get no hint and cost no judge call. An unsure, slow or failed judge adds nothing. With no `judge.json` nothing runs and nothing is logged. Each judged prompt leaves one decision-log line with the answer and the latency. The feature acts only when task 02's measured gate says `enabled`; at `log-only` it logs the lane it would have hinted and adds nothing. A repository can switch it off with `.fx.json` `"hooks": { "lane_hint": false }`, and this task adds the other two switches the later features read, `dispatch_sizing` and `edit_rules`, each on by default. The shell guard's circuit breaker moves into a shared `askJudgeWithBreaker` that keeps two separate breakers per session: the shell guard's, and one for the new features (lane hint, sizing, edit rules). A judge that keeps timing out on lane hints stops being asked for features, and the shell guard keeps asking it until its own calls fail; the guard's behaviour is otherwise unchanged. The same rule, held in memory for one run, serves `judge-review`, which has no session (task 11).

One hint has one overall deadline, `LANE_HINT_DEADLINE_MS` (2,500 ms): the second request goes out only when at least `JUDGE_BUDGET_MS` of it remains, so the hint never holds the prompt longer than 2,500 ms. A plain question (kind `other`, research `no`) costs exactly one request. This departs from design decision 3 as amended there (2026-10-24, plan red-team).

- Produces in `src/lib/judge-call.ts`:
  - `type Breaker = 'guard' | 'features'`
  - `askJudgeWithBreaker(handle: JudgeHandle, key: string | null, now: number, state: Record<string, string>, questions: Record<string, JudgeQuestion>, breaker: Breaker): Promise<JudgeResult>`. Never rejects. The journal kind is `judge` for `guard` and `feature-judge` for `features`; one breaker never reads or writes the other's events. With `handle.kind === 'ready'`, a non-null `key`, and that breaker open (its last `JUDGE_BREAKER_FAILURES` events in `readJournal(key)` all `ok: false` and the last under `JUDGE_BREAKER_COOLDOWN_MS` old), returns `{ ok: false, reason: 'circuit-open', detail: 'the judge failed 3 times in a row', latencyMs: 0 }` without a request. Otherwise calls `askJudge`, then appends `{ t: now, kind: <its kind>, ok: false }` when the result is a `timeout` or `network` failure, and `{ t: now, kind: <its kind>, ok: true }` when it is anything else and its last event was `ok: false`. A `null` key reads and writes no journal. With `breaker: 'guard'` this is the shell guard's existing rule, moved; `shellGuard` passes `'guard'`, every feature in this plan passes `'features'`.
  - `createRunBreaker(handle: JudgeHandle): (state: Record<string, string>, questions: Record<string, JudgeQuestion>) => Promise<JudgeResult>`: the same rule held in memory for one process run (for a caller with no session): after `JUDGE_BREAKER_FAILURES` consecutive `timeout` or `network` results, every later call in that run returns `circuit-open` without a request. Never rejects.
- Produces in `src/lib/lane-hint.ts`:
  - `interface LaneHintInput { harness: Harness; sessionId: string | null; cwd: string; prompt: string; now: number }`
  - `skipsLaneHint(prompt: string): boolean`: true when the trimmed prompt starts with `/`, starts with `[fx] `, matches the Stop sentence `/edited files and no check (?:has )?passed (?:since|after) the last edit/`, or has fewer than `LANE_MIN_WORDS` whitespace-separated words.
  - `decideLaneHint(input: LaneHintInput, judge?: JudgeHandle): Promise<string | null>`: never rejects (a throw inside returns `null` and writes `[fx] lane hint off: <message>` to stderr). Order: `skipsLaneHint` (null, no log); `featureMode('lane-hint', cwd) === 'off'` (null, no log); `judge ?? loadJudge()` not `ready` (null, no log); first request `LANE_FIRST_QUESTIONS` (`kind` and `research`) through `askJudgeWithBreaker` with `journalKey(sessionId)` and `'features'`; `laneAfterFirst` decides: a lane ends it, `'unsure'` ends it, `{ kind }` leads to a second request `{ lane: laneQuestion(kind) }`, sent only when `LANE_HINT_DEADLINE_MS` minus the time since the first request started is at least `JUDGE_BUDGET_MS`; otherwise no second request and the hint ends as unavailable with reason `deadline`. Returns `` `[fx] lane hint: ${laneAddress(harness, lane)}` `` only when the lane is not `none`, every answer was confident, and the mode is `enabled`.
  - Decision-log line for every judged prompt: `event: 'lane-hint'`, `text: ''` (the journal already holds the prompt), `latencyMs` the sum over both requests, `model`, `probabilities` and `escalate` of the deciding answer, and:
    - judge unavailable: `source: 'judge-down'`, `action: 'none'`, `unavailable: <reason>` (including `circuit-open` and `deadline`)
    - an unsure answer: `source: 'judge-unsure'`, `action: 'none'`, `answer: 'unsure'`
    - lane `none`: `source: 'judge'`, `action: 'none'`, `answer: 'none'`
    - mode `log-only`: `source: 'judge'`, `action: 'log-only'`, `answer: <lane>`
    - hint added: `source: 'judge'`, `action: 'hint'`, `answer: <lane>`
- Produces in `src/hooks/fx-turn.ts`: on `UserPromptSubmit` from the root session (no `agent_id`), after the prompt is journaled, stdout `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"<line>"}}` when `decideLaneHint` returns a line; nothing otherwise. Exit 0 on every path. `lib/lane-hint` is a typed `require` inside the existing `try`.
- Produces in `src/hooks/fx-codex.ts`: the same, from `recordPrompt`'s root-session path, only when task 01 recorded `MEASURED` acceptance of `additionalContext` on `UserPromptSubmit`. ## Acceptance criteria
- [ ] A request on Claude Code with a confident judge and the gate enabled gets exactly one `[fx] lane hint:` context line naming a lane that exists, and the user sees nothing.

- [ ] Skipped prompts, subagent prompts, no judge and a switched-off repository cost no judge call.
- [ ] Every judged prompt leaves one `lane-hint` decision-log line with answer and latency; at `log-only` nothing reaches the model.
- [ ] The shell guard's existing gates pass unchanged; a breaker opened by lane calls never stops the guard's calls, and the reverse.
- [ ] A plain question costs one judge request, and no hint holds a prompt longer than 2,500 ms.
- [ ] `scripts/check-all` prints `ALL GREEN`.
