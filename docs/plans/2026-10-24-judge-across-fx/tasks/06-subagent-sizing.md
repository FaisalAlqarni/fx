# 06: Subagent sizing

**Status:** ready-for-agent
**Blocked by:** 03
**Phase:** Core

**What to build:** when a general dispatch would run on sonnet (it named no model, or named `sonnet`) and carries no `Capable because:` line, fx asks the judge what kind of task it hands over. A confident read-only lookup or small fully specified edit runs on haiku, and the model gets one context line saying why; anything else keeps the model ADR 0031's rule gave it. A general dispatch that carries `Capable because:` is never rewritten: when the judge confidently calls it a lookup, the model gets one context line noting that, and the dispatch runs as asked. Typed agents (`fx:` lenses, other plugins' agents, `fork`, `Explore`) are never judged. With no judge, the switch `hooks.dispatch_sizing: false`, a judge failure, or the gate at `log-only`, the dispatch is exactly what ADR 0031's `route()` returns today, and `log-only` logs what sizing would have done. Only harnesses whose dispatch tool takes a model field are rewritten; task 01 recorded which. ADR 0031 found none outside Claude Code (Codex `rust-v0.155.1`, opencode `v1.18.25`), so unless task 01 found a model field in the installed Codex or opencode, this task changes Claude Code only and says so in each other harness's reference.

**Interfaces:**
- Consumes (task 01): `DISPATCH_KIND_QUESTION`, `DispatchKind`, `dispatchState`, `choiceVerdict` (`src/lib/judge-questions.ts`).
- Consumes (task 02): the measured `FEATURE_GATE['dispatch-sizing']` (scored as precision on `lower`), through `featureMode`.

- Produces in `src/lib/dispatch-route.ts`:
  - `isGeneralType(ti: DispatchInput): boolean`: `true` when `ti.subagent_type` is missing, empty, or one of `general-purpose`, `claude`, `Plan` (the existing `GENERAL` set).
  - `hasCapableLine(prompt: unknown): boolean`: the existing `/^\s*Capable because:/m` test on `String(prompt || '')`.
- Produces in `src/lib/dispatch-sizing.ts`:
  - `interface SizingInput { harness: Harness; sessionId: string | null; cwd: string; toolInput: unknown; now: number }`
  - `interface SizingResult { input: DispatchRoute; context: string | null }` (`input` is what the hook prints as `updatedInput`, `null` to leave the call alone)
  - `sizeDispatch(input: SizingInput, judge?: JudgeHandle): Promise<SizingResult>`. Never rejects (a throw returns `{ input: route(toolInput), context: null }` and writes `[fx] dispatch sizing off: <message>` to stderr). Rule:
    1. `base = route(toolInput)`. Not a record, or not `isGeneralType`: `{ input: base, context: null }`, no judge call.
    2. `featureMode('dispatch-sizing', cwd) === 'off'`, or `judge ?? loadJudge()` not `ready`: `{ input: base, context: null }`, no log.
    3. Unjustified (`!hasCapableLine(prompt)`) and the effective model (`base?.model ?? toolInput.model`) is `sonnet`: ask `{ kind: DISPATCH_KIND_QUESTION }` over `dispatchState(toolInput)`. A confident `lookup` or `small-edit`: `{ input: { ...toolInput, model: 'haiku' }, context: <sizing line> }`; anything else: `{ input: base, context: null }`.
    4. Justified (`hasCapableLine(prompt)`): ask the same question. A confident `lookup`: `{ input: base, context: <note line> }`; anything else `{ input: base, context: null }`. Never a model change.
    5. Any other dispatch (an unjustified general dispatch whose effective model is `haiku`): no judge call.
  - Exact lines: sizing `[fx] dispatch sizing: this dispatch runs on haiku because the judge read it as a read-only lookup.` (or `... as a small fully specified edit.` for `small-edit`); note `[fx] dispatch sizing: the judge read this dispatch as a read-only lookup; it keeps its model because it carries "Capable because:".`
  - Decision-log line for every judged dispatch: `event: 'dispatch'`, `text`: the dispatch `description` (redacted by the logger), `answer`: the kind or `unsure`, `model`, `probabilities`, `latencyMs`, `escalate`, and `source` / `action`: `judge` / `haiku`, `judge` / `note`, `judge` / `keep`, `judge-unsure` / `keep`, `judge-down` / `keep` (with `unavailable`), or `judge` / `log-only` when the gate is `log-only` (then the result is `{ input: base, context: null }` whatever the answer).
- Produces in `src/lib/types.ts`: `ClaudePreToolUseOutput` gains the form `{ hookSpecificOutput: { hookEventName: 'PreToolUse'; updatedInput?: DispatchInput; additionalContext?: string } }`.
- Hook output in `fx-pretooluse` for `Agent`/`Task`: `updatedInput` when `input` is not null, `additionalContext` when `context` is not null, both inside one `hookSpecificOutput`; the routing-off `systemMessage` as today; nothing when both are null. Exit 0 after stdout drains. An `uncaughtException` or `unhandledRejection` in this branch prints today's `route()` result (or nothing) and exits 0.

**Risks:** lowering a dispatch that needed judgement costs quality silently: only the two narrow kinds lower, only from sonnet, only when confident, only on general types, and the gate holds it to `log-only` until 85% of the judge's `lower` answers on the labelled set were right (precision on `lower`, task 02), because a wrong `lower` costs quality while a wrong `keep` costs only money. A rewritten prompt must be byte-identical apart from `model`: case 1 asserts it. The branch becomes asynchronous: stdout must still drain before exit.

**Testing:** process tests on the hook with the fake server, the routing gates as regression.
