# 13: Before/after benchmarks, ADR and docs

**Status:** ready-for-agent
**Blocked by:** 05, 06, 08, 09, 12
**Phase:** Polish

**What to build:** the owner can measure "faster and more accurate" with fx's own benches, and every reader can find what the judge now does. Both live benches (`tests/lane-triggering`, 17 prompts; `tests/review-bench`, 9 cases) accept `FX_BENCH_JUDGE=<path to a judge.json>`, which places that file as the judge config inside each run's scratch home, so the "after" run uses the owner's local judge on loopback; without it nothing changes. An offline test proves the placement without spending quota. `benchmark.md` in this plan's directory gives the exact before and after commands (before on the base checkout, after on this branch, both inside the conformance jail on Haiku 5.5 through OpenRouter as ADR 0038 sets up), a pilot step that checks the jail lets the judge's loopback port through, and an empty results table the owner fills. The agent runs no live bench. ADR 0048 records the decision: each judge question measured on a labelled set, the bars (precision on `lower` for sizing, the unsure-on-clean ceiling and minimum counts for edit rules), the judge and the scores from `scores.md`, the gate that followed, the catalogue rules that may refuse and the measured request concurrency, the harness facts from task 01, the design points the plan settled (one lane request carrying `kind` and `research`, a second only for `build`, `review` or `writing`, under one 2,500 ms deadline; the lane kinds grouped into 6 options; built-in edit rules checked in code; judged rules read the added lines, file-scope rules the post-edit file; only measured rules refuse; separate breakers for the shell guard and the new features), and one accepted gap: the agent can edit `.fx.json`, and fx only shows a notice when its rules or hook switches change during a session. It also says that the review bench measures fx's task reviewer, which the review helpers do not feed, so its after-run is a no-regression check and the helpers' accuracy is the `review-*` rows. An offline gate keeps ADR 0048's table and `FEATURE_GATE` in step. README and INSTALL describe the lane hint, sizing, edit rules with the picker and the three switches, and the review command.
