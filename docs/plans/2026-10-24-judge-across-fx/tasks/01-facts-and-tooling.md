# 01: Harness facts, questions and calibration tooling

**Status:** ready-for-agent
**Blocked by:** None: can start immediately
**Phase:** MVP

**What to build:** before any new judge decision reaches a session, fx knows the harness facts the later tasks branch on, has every new judge question and the state it reads written down in one module, and has the tooling to score each question and to measure whether the owner's judge serves concurrent requests. The facts: which harnesses' dispatch tools take a model field (Claude Code `Agent`, Codex `spawn_agent`, opencode 1.x `task`, opencode 2.x `subagent`); whether opencode 2.1.4 awaits a promise returned from a `tool.execute.before` callback before `permission.evaluate` runs; and whether Codex accepts `hookSpecificOutput.additionalContext` on `UserPromptSubmit` output (ADR 0023: an unknown key fails the hook run). Each is recorded in `references/harnesses/` as MEASURED or UNVERIFIED with the version and the evidence. The questions: lane kind, research or not, lane within kind, dispatch task kind, edit-rule breach (line or file scope), lens tripwire or lens focus, authored or generated, each with the state builder the hooks will send, inside 2 questions per request and 6 options per choice. `scripts/judge-calibrate.js` scores a labelled set for one feature, prints per-rule rows for edit rules, and has a `concurrency` mode that times the same requests sent one at a time and all at once. `src/lib/judge-features.ts` holds the bars and a gate that is `log-only` for every feature, an empty refusing-rule list and `sequential` concurrency, until task 02 writes the measured values. A new `scripts/scratch-env` runs any command with HOME, the XDG and Windows directories and TMPDIR pointed at a fresh scratch directory, and the test helper `scratchHookEnv` gains TMPDIR, so every later test run meets the owner's rule.

- Produces in `src/lib/judge-questions.ts` (exact wording; a change after task 02 measured it means measuring again):
  - `type LaneKind = 'build' | 'change' | 'failure' | 'review' | 'writing' | 'other'`
  - `LANE_KIND_QUESTION: JudgeQuestion`, choice, instructions `What kind of work does this request to a coding agent ask for?`, options in this order:
    - `build`: `a new feature, screen or behaviour, or a change to a design or plan`
    - `change`: `a code change whose behaviour the request already states`
    - `failure`: `something is broken, failing, slow or behaving unexpectedly`
    - `review`: `checking code: a diff, branch or pull request, or existing code as it stands`
    - `writing`: `writing or editing text for people or for agents`
    - `other`: `outside research, or none of these`
  - `RESEARCH_QUESTION: JudgeQuestion`, noul, instructions `Answering this request needs sources outside this repository: library documentation, a specification or the web.`
  - `KIND_LANES: Record<LaneKind, string[]>` = `build: ['fx-brainstorm', 'fx-design', 'prototype', 'fx-plan', 'fx-implement']`, `change: ['fx-tdd']`, `failure: ['fx-debug']`, `review: ['fx-review', 'fx-architecture']`, `writing: ['fx-humanize', 'fx-authoring']`, `other: ['research', 'none']`.
  - `laneQuestion(kind: LaneKind): JudgeQuestion | null`: `null` for `change`, `failure` and `other` (the first request settles them); otherwise a choice, instructions `Which of these fits the request best?`, options in `KIND_LANES[kind]` order with these descriptions: `fx-brainstorm` `new work whose design is not settled yet`; `fx-design` `how a screen or interface looks`; `prototype` `a throwaway build to settle a question by trying it`; `fx-plan` `an approved design that needs breaking into tasks`; `fx-implement` `a written plan that needs building`; `fx-review` `checking changed code: a diff, branch or pull request`; `fx-architecture` `assessing existing code that has no diff`; `fx-humanize` `prose written for people`; `fx-authoring` `a document an agent reads: a skill, prompt, CLAUDE.md or AGENTS.md`.
  - `LANE_FIRST_QUESTIONS: Record<string, JudgeQuestion>` = `{ kind: LANE_KIND_QUESTION, research: RESEARCH_QUESTION }` (the first lane request, two questions).
  - `laneAfterFirst(answers: Record<string, JudgeAnswer> | undefined): { lane: string } | { kind: LaneKind } | 'unsure'`: `choiceVerdict(answers?.kind)`; `unsure` gives `'unsure'`; `change` and `failure` give `{ lane: KIND_LANES[kind][0] }`; `other` gives `{ lane: 'research' }` when `noulVerdict(answers.research)` is `yes`, `{ lane: 'none' }` when `no`, `'unsure'` otherwise; `build`, `review` and `writing` give `{ kind }` (a second request asks `laneQuestion(kind)`).
  - `type DispatchKind = 'lookup' | 'small-edit' | 'implementation' | 'design-review' | 'security' | 'side-effect'`
  - `DISPATCH_KIND_QUESTION: JudgeQuestion`, choice, instructions `What kind of task does this subagent dispatch hand over?`, options in this order: `lookup` `read-only: find, read, list or answer a question about code, changing nothing`; `small-edit` `a small edit whose exact change the prompt spells out`; `implementation` `building or changing behaviour that needs judgement`; `design-review` `designing, planning or reviewing`; `security` `anything touching authentication, secrets, permissions or user data`; `side-effect` `running commands that change things outside the repository: deploys, publishes, deletes, migrations`.
  - `editRuleQuestion(rule: EditRule): JudgeQuestion`: noul; instructions `` `The added lines break this rule: ${rule.rule}` `` when `rule.scope` is absent, `` `The file after this change breaks this rule: ${rule.rule}` `` when `rule.scope === 'file'`.
  - `focusQuestion(focus: string, unit: 'change' | 'function'): JudgeQuestion`: noul, instructions `` `This ${unit === 'change' ? 'code change' : 'function'} contains any of the following: ${focus}` ``.
  - `AUTHORED_QUESTION: JudgeQuestion`, choice, instructions `Was this file written by a person, or produced by a tool?`, options: `authored` `written by a person for this change`; `generated` `produced by a tool: a framework skeleton, a lock file, compiled or bundled output, a snapshot`.
  - `lensFocus(reviewSkill: string): Record<string, { tripwire: string | null; focus: string }>`: parses the lens table of `skills/fx-review/SKILL.md` (rows starting `` | `fx-lens- ``). `tripwire` is the second cell with its leading `tripwire: ` removed, or `null` when the cell is `no`; `focus` is `tripwire` when non-null, else the third cell. Throws `Error('the lens table in fx-review is missing')` when no row is found.
  - State builders (the hooks and the calibration send exactly these):
    - `laneHintState(prompt: string, cwd: string, harness: Harness): Record<string, string>` gives `{ prompt, cwd: path.basename(cwd), harness }`.
    - `dispatchState(ti: DispatchInput): Record<string, string>` gives `{ subagent_type, description, prompt }`: `subagent_type` is `ti.subagent_type` when a non-empty string, else `general-purpose`; `description` and `prompt` the strings given, else `''`.
    - `editRuleState(relPath: string, added: string, file?: string): Record<string, string>` gives `{ path: relPath, added: added.slice(0, EDIT_TEXT_CHARS) }`, plus `file: file.slice(0, EDIT_FILE_CHARS)` when `file` is given.
    - `diffState(chunk: string): Record<string, string>` gives `{ change: chunk }`.
    - `authoredState(relPath: string, head: string): Record<string, string>` gives `{ path: relPath, head }` where `head` is the first 40 lines, cut to `REVIEW_CHUNK_CHARS`.
    - `unitState(relPath: string, name: string | null, text: string): Record<string, string>` gives `{ path: relPath, function: name ?? '(changed lines)', text }`.
  - `choiceVerdict(a: JudgeAnswer | undefined): string | 'unsure'`: the choice when `a` is a choice answer with `escalate === null`, else `'unsure'`.
  - `noulVerdict(a: JudgeAnswer | undefined, yesAt = NOUL_UNSURE_HIGH): 'yes' | 'no' | 'unsure'`: for a noul answer, `'yes'` when `p >= yesAt` and `escalate === null`, `'no'` when `p < NOUL_UNSURE_LOW`, else `'unsure'`; `'unsure'` for anything else.
- Produces in `src/lib/judge-features.ts`:

  - `type FeatureGate = 'enabled' | 'log-only'`
  - `interface FeatureBar { metric: 'accuracy' | 'precision'; positive: string | null; bar: number; minConfident: number; maxUnsureClean: number | null }`
  - `FEATURE_BARS: Record<JudgeFeature, FeatureBar>` = `edit-rules` `{ metric: 'precision', positive: 'breach', bar: 0.95, minConfident: 30, maxUnsureClean: UNSURE_CLEAN_MAX }`; `dispatch-sizing` `{ metric: 'precision', positive: 'lower', bar: 0.85, minConfident: 20, maxUnsureClean: null }`; `review-tripwires` and `review-search` `{ metric: 'accuracy', positive: null, bar: 0.85, minConfident: 40, maxUnsureClean: null }`; `lane-hint` and `review-authored` `{ metric: 'accuracy', positive: null, bar: 0.85, minConfident: 20, maxUnsureClean: null }`.

  - `REFUSING_RULES: readonly string[]`: `[]` in this task; task 02 writes the ids of the catalogue rules whose own labelled items cleared the refusal bar.
  - `JUDGE_CONCURRENCY: 'concurrent' | 'sequential'`: `sequential` in this task; task 02 writes the measured mode.
  - `gateOf(feature: JudgeFeature): FeatureGate`: `FEATURE_GATE[feature]`, except when `process.env.FX_TEST === '1'` and `process.env.FX_FEATURE_GATE` (comma-separated `<feature>=<gate>` pairs) names this feature with a valid gate; then that gate.
  - `refusingRule(id: string): boolean`: `REFUSING_RULES.includes(id)`, except when `FX_TEST === '1'` and `FX_REFUSING_RULES` is set: then whether that comma-separated list holds `id`.
  - `concurrencyOf(): 'concurrent' | 'sequential'`: `JUDGE_CONCURRENCY`, except when `FX_TEST === '1'` and `FX_JUDGE_CONCURRENCY` is `concurrent` or `sequential`: then that value.

- Produces in `src/lib/judge-score.ts`:
  - `interface ScoredItem { label: string; predicted: string; latencyMs: number; unavailable: boolean }` (`predicted` is `'unsure'` for an unsure answer)
  - `interface FeatureScore { feature: JudgeFeature; metric: 'accuracy' | 'precision'; value: number; confident: number; total: number; unavailable: number; unsureClean: number | null; medianMs: number; maxMs: number; gate: FeatureGate }`
  - `scoreFeature(feature: JudgeFeature, items: ScoredItem[]): FeatureScore`. Accuracy: `confident` counts items with `predicted !== 'unsure'` and not unavailable; `value` is correct confident items over `confident` (0 when none). Precision (bar `positive` set): `confident` counts items predicted `positive`; `value` is those labelled `positive` over `confident` (0 when none). `unsureClean` (only when `maxUnsureClean` is not null, else `null`): items labelled other than `positive` and predicted `unsure`, over all items labelled other than `positive` and not unavailable (0 when none). `medianMs` is the latency at index `Math.floor(n / 2)` of the sorted list, `maxMs` the largest. `gate` is `enabled` when `value >= bar`, `confident >= minConfident`, and `unsureClean <= maxUnsureClean` where that bar is set; else `log-only`.
  - `scoreRow(s: FeatureScore): string` gives `` `| ${feature} | ${metric} | ${Math.round(value * 100)}% | confident ${confident}/${total} | unsure-clean ${unsureClean === null ? 'n/a' : Math.round(unsureClean * 100) + '%'} | bar ${bar * 100}% | ${gate} | median ${medianMs} ms | max ${maxMs} ms |` ``.
  - `interface RuleScore { rule: string; value: number; confident: number; total: number; unsureClean: number; refuses: boolean }` and `scoreRules(items: (ScoredItem & { rule: string })[]): RuleScore[]`: the `edit-rules` precision, confident count and unsure-on-clean rate per rule id, in first-seen order; `refuses` when that rule alone meets every `edit-rules` bar (`0.95`, 30 confident, unsure-on-clean at most `UNSURE_CLEAN_MAX`).
  - `ruleRow(r: RuleScore): string` gives `` `| rule ${rule} | precision | ${Math.round(value * 100)}% | confident ${confident}/${total} | unsure-clean ${Math.round(unsureClean * 100)}% | bar 95% | ${refuses ? 'refuses' : 'advises'} |` ``.
  - `interface ConcurrencyScore { mode: 'concurrent' | 'sequential'; sequentialMedianMs: number; concurrentMaxMs: number; concurrentFailures: number }` and `scoreConcurrency(sequentialMs: number[], concurrentMs: number[], concurrentFailures: number): ConcurrencyScore`: `concurrent` only when `concurrentFailures === 0`, every concurrent latency is at most `JUDGE_BUDGET_MS`, and the largest is at most 1.5 times the sequential median; else `sequential`.
  - `concurrencyRow(c: ConcurrencyScore): string` gives `` `| concurrency | ${mode} | sequential median ${sequentialMedianMs} ms | concurrent max ${concurrentMaxMs} ms | failures ${concurrentFailures} |` ``.

**How each feature is scored** (`judge-calibrate`): `lane-hint` asks `LANE_FIRST_QUESTIONS`; `laneAfterFirst` decides; only for `{ kind }` it asks `{ lane: laneQuestion(kind) }` in a second request; the prediction is the lane, `unsure` if any answer is. `dispatch-sizing` asks `{ kind: DISPATCH_KIND_QUESTION }`; label and prediction are `lower` for `lookup` or `small-edit` and `keep` for the rest. `edit-rules` asks `{ breach: editRuleQuestion(<the entry's rule>) }` over `editRuleState(path, added, file)`; a noul answer with `p >= EDIT_BREACH_MIN_P` and no escalation predicts `breach`, `noulVerdict` `no` predicts `clean`, anything else `unsure`. `review-tripwires` asks `{ hit: focusQuestion(<the lens tripwire from lensFocus>, 'change') }` over `diffState`; a noul answer with `p >= REVIEW_ADD_MIN_P` and no escalation predicts a hit, `noulVerdict` `no` a miss, anything else `unsure`. `review-authored` asks `{ origin: AUTHORED_QUESTION }` over `authoredState`; `review-search` asks `{ flag: focusQuestion(<lens focus>, 'function') }` over `unitState`, yes and no from `noulVerdict`.
