# 05: Lane hint on opencode 1.x and 2.x

**Status:** ready-for-agent
**Blocked by:** 03, 04
**Phase:** Core

**What to build:** on opencode, a user's new message to a primary agent gets the same lane hint as on Claude Code: the judge picks the kind and the lane, and one `[fx] lane hint: <lane>` line reaches the model in that turn's system text, never the terminal. opencode cannot tell a user's message from a parent agent's prompt to a child session (`references/harnesses/opencode.md`), so the hint is given only when the message is addressed to a primary agent: opencode's built-in `build` or `plan`, or an agent the user's config defines with `mode` `primary` or `all`. A child session runs a subagent (`general`, fx's own agents), so it gets no hint. On 1.x the hint is decided in `chat.message` and queued for that session; the next `experimental.chat.system.transform` for the session pushes it. On 2.x the same runs from the prompt hook and the context hook, but only where the runtime waits for plugin callbacks (task 04's `V2_AWAITS_BEFORE`) and the 2.1.4 prompt event's text and agent fields are read from the installed binary; otherwise 2.x gets no hint and its reference says why. Everything else (skips, gate, switch, log line, breaker, no judge means no work) is task 03's `decideLaneHint`, unchanged.

**Interfaces:**
- Consumes (task 03): `decideLaneHint(input: LaneHintInput, judge?: JudgeHandle): Promise<string | null>` and `LaneHintInput` (`src/lib/lane-hint.ts`).
- Consumes (task 04): `V2_AWAITS_BEFORE` (`src/plugins/fx-opencode-v2.ts`).
- Consumes (existing): `createQueue` (`enqueue`, `startTurn`, `drain`) from `src/lib/opencode-queue.ts`; `parseOpencodeAgent` (`src/lib/opencode-input.ts`).
- Produces in `src/lib/opencode-agents.ts`: `isPrimaryAgent(agent: string | undefined, configured: Record<string, unknown> | undefined): boolean`: `false` for `undefined`; `true` for `build` and `plan` unless `configured[agent]` is an object whose `mode` is `subagent`; `true` for a configured agent whose `mode` is `primary` or `all`; `false` otherwise.
- Produces in `src/lib/opencode-input.ts`:
  - `parseOpencodeV1PromptText(output: unknown): string | undefined`: the `text` of every `output.parts` entry with `type` `text`, joined by `\n`; `undefined` when there is none.
  - `parseOpencodeV2PromptText(ev: unknown): string | undefined`: reads the field task 05 step 2 records for 2.1.4; `undefined` when absent.
- 1.x order in `chat.message`: the existing `queue.startTurn` and Stop reminder, then the journal mark, then, when `isPrimaryAgent(parseOpencodeAgent(input), <config.agent>)` and the text is defined, `decideLaneHint({ harness: 'opencode', sessionId, cwd, prompt, now })` and `queue.enqueue(session, line)` for a non-null line. A throw writes `[fx] lane hint off: <message>` once per plugin instance and changes nothing else.

**Seam:** both plugins in-process with a fake `ctx` or hook inputs under `applyScratchEnv()` and the fake `/v1/systemone` server; `isPrimaryAgent` and the text parsers directly.

**Tests:**
- `isPrimaryAgent('build', undefined)` true; `isPrimaryAgent('general', undefined)` false; `isPrimaryAgent(undefined, {})` false; `isPrimaryAgent('docs', { docs: { mode: 'primary' } })` true; `isPrimaryAgent('docs', { docs: { mode: 'all' } })` true; `isPrimaryAgent('build', { build: { mode: 'subagent' } })` false; `isPrimaryAgent('fx-lens-security', {})` false.
- `parseOpencodeV1PromptText({ parts: [{ type: 'text', text: 'a b' }, { type: 'file', url: 'x' }, { type: 'text', text: 'c' }] })` is `a b\nc`; `parseOpencodeV1PromptText({ parts: [] })` is `undefined`; `parseOpencodeV1PromptText(null)` is `undefined`.
- 1.x in-process, gate `lane-hint=enabled`, after `config({ agent: {} })`:
  1. `chat.message({ sessionID: 's', agent: 'build', messageID: 'm' }, { message: {}, parts: [{ type: 'text', text: 'please add a CSV export to the report page' }] })`, judge answers `kind: build 0.9`, `research: p=0.05`, then `lane: fx-brainstorm 0.9`; then `experimental.chat.system.transform({ sessionID: 's' }, out)`: `out.system` contains `[fx] lane hint: fx-brainstorm` exactly once; a second transform for `s` does not contain it; the first request's `state.harness` is `opencode`; one log line `event` `lane-hint`, `harness` `opencode`, `action` `hint`.
  2. The same message with `agent: 'general'`: zero requests; no hint line.
  3. The same message with `agent: 'docs'` after `config({ agent: { docs: { mode: 'primary' } } })`: one hint line.
  4. Gate `lane-hint=log-only`: no hint line in the transform; log `action` `log-only`.
  5. No `judge.json`: zero requests; the Stop reminder and journal mark behave as before (the existing `opencode-turn` gate passes unchanged).
  6. A judge delaying 3,000 ms: `chat.message` resolves in under 2,500 ms; no hint line.
- 2.x, when `V2_AWAITS_BEFORE` is true and step 2 recorded the fields as MEASURED: the prompt hook event built from the recorded field names, `agent` `build`, the same prompt and answers as case 1: the next `context` call for that session pushes `{ type: 'text', text: '[fx] lane hint: fx-brainstorm' }` once. Otherwise: the same event makes zero requests, and `references/harnesses/opencode-v2.md` "Turn boundary and health line" contains `fx gives no lane hint on 2.x:` followed by the reason.
- `references/harnesses/opencode.md` "Plugin events fx reads" contains `GAP: a slash command reaches chat.message as its expanded text, so fx cannot skip the lane hint for it on 1.x.`

**Risks:** a slash command on 1.x arrives as its expanded template, so it can get a hint; recorded as a GAP, it costs one judge call and one context line. An unmeasured 2.x field fails toward no hint. The hint waits on the judge before the first model request of the turn; the budget, the skip rule and the breaker from task 03 bound that.

**Testing:** unit tests for the agent rule and the text parsers; in-process plugin tests with the fake server; the existing opencode gates as regression.
