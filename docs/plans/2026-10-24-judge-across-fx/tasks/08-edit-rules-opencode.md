# 08: Edit rules on opencode 1.x and 2.x

**Status:** ready-for-agent
**Blocked by:** 04, 07
**Phase:** Core

**What to build:** opencode users get the same edit rules as Claude Code and Codex. On 1.x, `tool.execute.before` for `edit`, `write` and `apply_patch` awaits `checkEdit` after the fx-state refusal and the lane check: a refusal (a built-in breach, or a confident breach of a measured rule) throws `[fx] rule <id>: <rule> (<file>)`, which is how 1.x refuses a tool call; an advisory queues its line for that session's next system text; anything else lets the call run. On 2.x the built-in rules run synchronously in `tool.execute.before` for the edit tool and a breach throws there, which refuses the call cleanly (probe Q4), whatever task 04 found. The judged rules run there too: where task 04 found the runtime awaits the callback (`V2_AWAITS_BEFORE`), `checkEdit` is awaited and refuses as on 1.x; where it does not, or the fact is UNVERIFIED, the judged check runs without blocking the call and every result, a would-be refusal included, only advises through the session's queue. The 2.x edit tool's input field names are read from the installed 2.1.4 binary first and recorded. On 1.x the Stop check's `.fx.json` notice (task 07) is queued for the session beside the Stop reminder; 2.x has no Stop check and no session on its health line, so it gets no notice, recorded as a GAP. A crash or load failure in the rule check allows the edit on both majors.

**Interfaces:**
- Consumes (task 07): `checkEdit(input: EditCheckInput, judge?: JudgeHandle): Promise<EditRuleDecision>`, `EditCheckInput`, `EditRuleDecision`, `changedFiles`, `builtinBreach` (`src/lib/edit-rules.ts`); `decideStop`'s `notice`.
- Produces in `src/lib/edit-rules.ts`: `checkBuiltins(input: EditCheckInput): EditRuleDecision`, synchronous: steps 1 and 2 of `checkEdit` (the switch, then the built-in rules), returning `refuse` with the same reason and log line, or `allow`. `checkEdit` calls it first, so its behaviour is unchanged.
- Consumes (task 04): `V2_AWAITS_BEFORE` (`src/plugins/fx-opencode-v2.ts`).
- Consumes (existing): the 1.x plugin's `queue` (`createQueue`), `warnOnce`, `namesFxState`, `hardReason`, `laneCheck`, and the queue it uses for the Stop reminder; the 2.x plugin's `parseEvent`, `queue`, `warnOnce`.
- 1.x Stop: when `decideStop` returns a non-null `notice`, it is enqueued for the session beside the reminder.
- 1.x behaviour in `tool.execute.before`, after the existing loops: `checkEdit({ harness: 'opencode', sessionId: event.value.sessionID ?? null, cwd, toolName: tool, toolInput: args, now: Date.now() })`; `refuse` throws `new Error(reason)`; `advise` enqueues the reason for the session (when a session id is present); `allow` returns. A throw inside `checkEdit` cannot happen (it never rejects); a failed load of `lib/edit-rules` is reported once with `warnOnce('[fx] edit rules off: <message>')` and allows.
- 2.x behaviour in `execute.before`, for the edit tool name recorded in "Tool vocabulary", with `input = { harness: 'opencode-v2', sessionId, cwd: ctx.location.directory, toolName, toolInput: ev.input, now }`: first `checkBuiltins(input)`, whose `refuse` throws `new Error(reason)` synchronously. Then, when `V2_AWAITS_BEFORE`: `await checkEdit(input)`; `refuse` throws `new Error(reason)`; `advise` enqueues for the session. When not: `checkEdit(input)` is started and not awaited; when it settles, a `refuse` or `advise` reason is enqueued for the session as advice, prefixed `[fx] advice only on opencode 2.x: `.

**Seam:** both plugins in-process under `applyScratchEnv()` with the fake server; `checkBuiltins` and `changedFiles` directly for the 2.x field names.

**Risks:** a 1.x refusal by throw is the same mechanism the git guard uses, so the agent sees the text. An unmeasured 2.x field name fails toward no check, never toward a refusal. On a non-awaiting 2.x the judge's advice arrives after the edit landed; it names the file, so the agent can revisit it. The advisory on opencode arrives with the next model request, not alongside the tool result; that is the queue's existing delivery and it is advice.

**Testing:** in-process plugin tests with the fake server; the existing opencode gates as regression.

## Acceptance criteria
- [ ] On opencode 1.x a built-in breach, or a confident breach of a measured rule, on `edit`, `write` or `apply_patch` refuses the call with the rule and file named; a write that only adds clean lines to a file with an old em dash is allowed.
- [ ] On 2.x built-in breaches refuse everywhere; judged refusals hold where the runtime awaits `execute.before`, and only advise elsewhere, as its reference says.
- [ ] An unsure answer reaches the model as one queued advisory line; no judge or a failure lets the edit through.
- [ ] `scripts/check-all` prints `ALL GREEN`.
