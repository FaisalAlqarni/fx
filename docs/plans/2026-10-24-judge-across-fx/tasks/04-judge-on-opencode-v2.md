# 04: Judge on opencode 2.x

**Status:** ready-for-agent
**Blocked by:** 01
**Phase:** Core

**What to build:** opencode 2.x users get the judge exactly when the runtime waits for it. Task 01 recorded, under "Shell guard" in `references/harnesses/opencode-v2.md`, whether opencode 2.1.4 awaits a promise returned from a `tool.execute.before` callback before `permission.evaluate`. If it is MEASURED as awaited, the 2.x plugin runs the full shell guard (hard rules, allowlist, repo commands, judge, loop guard) in `execute.before` and leaves the decision for `evaluate` to apply after the git guard: a judge deny refuses, an ask uses 2.x's own ask, a warn goes to stderr. No `# fx-ok` stamp is honoured on 2.x, and the refusal text says so instead of offering one. If it is not awaited, or UNVERIFIED, 2.x stays rules-only, and the reference and the plugin header say so with the measured evidence; no code path changes. Either way the plugin exports one constant later tasks read, so the lane hint and the edit rules on 2.x follow the same fact.

**Design:** Implementation Decisions > 9; Implementation Decisions > 2; Global Constraints

**Interfaces:**
- Consumes (task 01): the "Shell guard" fact in `references/harnesses/opencode-v2.md`.
- Consumes (existing): `guardShell`, `guardShellCodeOnly` (`src/lib/shell-guard.ts`); `GuardDecision`; `callKey`, `commands`, `shellGuard`, `deny` inside the plugin.
- Produces in `src/plugins/fx-opencode-v2.ts`: `const V2_AWAITS_BEFORE: boolean`, `true` only when task 01 recorded MEASURED awaiting, with a one-line comment citing the reference section. Tasks 05 and 08 branch on it.
- Branch A produces, inside the plugin: a `decisions: Map<string, GuardDecision>` keyed by `callKey`, filled in `execute.before` by `await guardShell({ command, cwd: ctx.location.directory, harness: 'opencode-v2', sessionId, now: Date.now(), posix })` after the command is recorded; read and deleted in `evaluate` after the git guard allows; deleted in `execute.after`. `evaluate` applies it: `deny` sets `effect` `deny` and `message` the reason; `ask` sets `effect` `ask` and `message` the reason; `warn` writes the reason to stderr; `allow` changes nothing. A call with no stored decision (the before hook threw, or the key was missing) falls back to today's `shellGuard` with `guardShellCodeOnly`. A hard rule found in `evaluate` still denies whatever the stored decision says.
- Branch A changes in `src/lib/shell-guard.ts`: the judge-deny follow-on text is `NO_AGREEMENT` (`fx cannot take the user's agreement on this harness; the user can run the command themselves.`) for `opencode-v2` as for `opencode`; every other harness's text is unchanged.

**Seam:** the 2.x plugin in-process with a fake `ctx` under `applyScratchEnv()`, the fake `/v1/systemone` server, `execute.before` then `evaluate` for the same `sessionID`, `messageID` and `id`.

**Tests:**
- Both branches: `V2_AWAITS_BEFORE` equals whether the "Shell guard" section of `references/harnesses/opencode-v2.md` holds a paragraph starting `MEASURED` that says the promise is awaited (the gate reads the file and the built plugin's export or source).
- Branch A, fake `ctx`, events `before = { tool: 'shell', sessionID: 's', messageID: 'm', id: 'c', input: { command: <cmd> } }` and `ev = { action: 'shell', sessionID: 's', source: { messageID: 'm', id: 'c' }, resources: [<cmd>], effect: 'allow' }`:
  1. `npm publish`, judge answers `decision: deny 0.91`: after `await before(...)` and `evaluate(ev)`, `ev.effect` `deny`, `ev.message` `[fx] shell guard denied: the judge answered deny (p=0.91). fx cannot take the user's agreement on this harness; the user can run the command themselves.`; one request whose `state.harness` is `opencode-v2`; one log entry `source` `judge`, `action` `deny`.
  2. `npm publish`, `decision: ask 0.70`: `ev.effect` `ask`, `ev.message` `[fx] shell guard asks: the judge answered ask (p=0.70). Confirm with the user before running it.`
  3. `ls | wc -l`, `decision: run 0.9`: `ev.effect` stays `allow`, `ev.message` undefined.
  4. `rm -rf ~`, judge configured: `ev.effect` `deny`, `ev.message` `[fx] refused: rm -r on a root, home or system directory cannot be undone. This rule has no override.`; zero requests.
  5. `npm publish`, no `judge.json`: `ev.effect` `allow`; log `source` `no-judge`.
  6. `npm publish`, judge delaying 3,000 ms: `before` resolves in under 2,500 ms; `ev.effect` `allow`; log `source` `judge-down`, `unavailable` `timeout`.
  7. `evaluate` with no prior `before` for the key: today's result (`guardShellCodeOnly`: `ev.effect` `allow`, log `source` `judge-unsupported` for `npm publish`).
  8. `git push --force origin main`, judge answering run: `ev.effect` `deny` and `ev.message` the git guard's existing reason for that command (the judge's `run` stored in `before` does not override the git guard).
  9. A `before` whose `guardShell` rejects (module replaced in a scratch copy with one returning `Promise.reject(new Error('async'))`): `before` resolves, stderr holds `[fx] shell guard off: async`, and `evaluate` falls back as in case 7.
- Branch A: `node lib/shell-guard.test.js` gains: `guardShell` on `opencode` and on `opencode-v2` with judge deny 0.91 give the same no-agreement reason; on `claude-code` the stamp text is unchanged.
- Branch B: the existing `opencode-v2-shell-guard` gate passes unchanged, and `references/harnesses/opencode-v2.md` "Shell guard" no longer contains `UNVERIFIED, code rules only.` but a paragraph starting `MEASURED` or `UNVERIFIED` dated 2026-10 naming 2.1.4 and ending `so 2.x runs code rules only.`

**Risks:** branch A puts a judge call on every grey 2.x shell command before the permission prompt; the budget and the shell guard's own breaker (`askJudgeWithBreaker` with `'guard'`, task 03) bound it. A decision stored for a call opencode then cancels stays in the map until `execute.after`; cap the map at 200 entries, dropping the oldest, as a bounded memory. Never let a stored `allow` skip the git guard: `evaluate` keeps the git guard first.

**Testing:** in-process plugin tests with a fake `ctx` and the fake server; the existing 2.x gates as regression.
