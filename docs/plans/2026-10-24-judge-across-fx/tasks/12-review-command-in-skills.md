# 12: Review command in fx-implement and fx-review

**Status:** ready-for-agent
**Blocked by:** 11
**Phase:** Review

**What to build:** the controller of fx-implement and the runner of fx-review use `judge-review` where a lens is chosen and briefed. Per task, after reading the implementer's `Tripwires:` line, the controller runs `tripwires` and dispatches every lens the line named plus every lens in `add`; then runs `search` for the lenses it is dispatching and pastes each lens's `brief` into that lens's brief. In fx-review's branch pass, and in a review with no ledger, the runner first runs `authored` and drops the generated files from the file-pattern triggers ("match on authored content", which the skill already demands), naming them in each lens brief as `Generated, not authored: <files>`, then runs `search` for the lenses it dispatches. Four rules are written into both skills: a lens the `Tripwires:` line named always runs, whatever the command prints; a lens in `unchecked` is neither added nor dropped by the command; a generated file never removes a lens the report named; and when the command fails, prints `"judge": "none"`, `"invalid"` or `"log-only"`, the review runs exactly as it does today. Lenses still read the whole diff: the search block only says where to start.

[--harness <name>]` and its JSON outputs: `tripwires` `{ judge, named, add, unchecked }`; `authored` `{ judge, generated: { file, reason }[], authored, unchecked }`; `search` `{ judge, lenses: Record<string, { flagged, unchecked, brief }> }`.
- The command lines the skills give, exactly (the skill's base directory is where the lane was loaded from, as `compile-brief` is already addressed):
  - fx-implement: `node <skill base directory>/../../lib/judge-review.js tripwires --package <diff file> --report <report file> --root <worktree> --harness <this harness>` and `node <skill base directory>/../../lib/judge-review.js search --package <diff file> --root <worktree> --lens <lens> [--lens <lens>]... --harness <this harness>`
  - fx-review: `node <skill base directory>/../../lib/judge-review.js authored --package <diff file> --root <repo root> --harness <this harness>` and the same `search` line with `--root <repo root>`.
- Sentences both skills carry verbatim (the gate pins them):
  - `A lens the \`Tripwires:\` line named always runs, whatever the command prints.`
  - `A lens in \`unchecked\` is neither added nor dropped: the judge could not answer for it.`
  - `When the command fails or prints "judge": "none", "invalid" or "log-only", dispatch exactly as you would without it.`
  - `Paste each lens's \`brief\` into that lens's brief, below the mode line; the lens still reviews the whole diff.`
- fx-review only: `A file \`authored\` lists as generated is dropped from the file-pattern triggers and named in each lens brief as \`Generated, not authored: <files>\`; it never removes a lens the report named.`
