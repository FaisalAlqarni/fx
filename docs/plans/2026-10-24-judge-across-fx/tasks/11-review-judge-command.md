# 11: Review judge command

**Status:** ready-for-agent
**Blocked by:** 02, 03, 10
**Phase:** Review

**What to build:** a command the fx-implement controller and fx-review run on a review package (the file `skills/fx-implement/scripts/review-package` writes), since lenses have no shell. `node lib/judge-review.js tripwires` asks, per per-task lens tripwire in the fx-review lens table, whether the diff hits it, and returns the lenses to add beyond those the implementer's `Tripwires:` line named; it never returns a removal and never asks about a lens the line already named. `authored` sorts each changed file into generated or authored: lock files and files carrying a generated marker by name and content, the rest by the judge. `search` splits each changed file into the functions the diff touched (task 10) and asks each requested lens's question per function, returning the flagged functions with file and line and a ready-made block of text for that lens's brief. Large diffs and long functions are cut into chunks that fit the local judge; a chunk the judge could not answer is listed as unchecked, never as clean. With no judge the command makes no request and returns empty results; with a feature's gate at `log-only` it asks and logs but returns empty results. Output is one JSON object on stdout.

**Interfaces:**
- Consumes (task 01): `focusQuestion`, `AUTHORED_QUESTION`, `lensFocus`, `diffState`, `authoredState`, `unitState`, `noulVerdict`, `choiceVerdict` (`src/lib/judge-questions.ts`); `gateOf`, `concurrencyOf` (`src/lib/judge-features.ts`); `REVIEW_CHUNK_CHARS`, `REVIEW_MAX_IN_FLIGHT`, `REVIEW_ADD_MIN_P`; decision-log event `review`, field `answer`.
- Consumes (task 02): the measured `FEATURE_GATE` rows for `review-tripwires`, `review-authored` and `review-search`, and `JUDGE_CONCURRENCY`.
- Consumes (task 03): `createRunBreaker(handle: JudgeHandle)` (`src/lib/judge-call.ts`): every request this command makes goes through one run breaker, so a judge that times out or cannot connect three times in a row is not asked again in that run and the rest is reported unchecked.
- Consumes (task 10): `reviewUnits(filePath: string, source: string, changedLines: number[]): ReviewUnit[]`, `ReviewUnit` (`src/lib/function-split.ts`).
- Consumes (existing): `loadJudge` (`src/lib/judge.ts`); `logDecision`.
- Produces in `src/lib/review-input.ts`:
  - `interface DiffHunk { newStart: number; added: number[]; text: string }` (`added`: new-file line numbers of `+` lines; `text`: the hunk's lines including its `@@` header)
  - `interface DiffFile { path: string; deleted: boolean; hunks: DiffHunk[] }`
  - `parseReviewPackage(text: string): DiffFile[]`: reads the `## Diff` section's `diff --git a/<p> b/<p>` blocks; `path` is the `b/` path; `deleted` when `+++ /dev/null`; never throws; text with no diff gives `[]`.
  - `parseTripwiresLine(report: string): string[]`: the first line starting `Tripwires:`; each word `security`, `database`, `silent-failure`, or a full `fx-lens-<name>`, mapped to `fx-lens-<name>`, each once; `none` or no line gives `[]`.
- Produces `node lib/judge-review.js <tripwires|authored|search> --package <file> [--root <dir>] [--report <file>] [--lens <name>]... [--harness <claude-code|codex|opencode|opencode-v2>]`. `--root` defaults to the current directory, `--harness` to `claude-code`. The lens table is read from `skills/fx-review/SKILL.md` beside the script (`path.join(__dirname, '..', 'skills', 'fx-review', 'SKILL.md')`). Exit 0 with one JSON object on stdout for every run that parsed its arguments; exit 2 with `usage: judge-review tripwires|authored|search --package <file> [--root <dir>] [--report <file>] [--lens <name>]... [--harness <name>]` on stderr for bad arguments, and `judge-review: cannot read <file>` for an unreadable package. Every output has `judge`: `none` (no `judge.json`), `invalid` (a broken one), `log-only` or `enabled` (that subcommand's `gateOf`).
  - `tripwires` output `{ judge, named: string[], add: string[], unchecked: string[] }`. `named` is `parseTripwiresLine` of `--report` (`[]` without one). Asked lenses: those whose `lensFocus` tripwire is not null and that `named` does not hold. The diff (each file's `diff --git` line plus its hunks, deleted files included) is cut into chunks of at most `REVIEW_CHUNK_CHARS` (a hunk longer than that is cut by lines); per chunk, the asked lenses in pairs, questions `q0`, `q1`, each `focusQuestion(<tripwire>, 'change')`, state `diffState(chunk)`. A chunk counts as a hit only when its noul `p >= REVIEW_ADD_MIN_P` (0.9) with no escalation; a `yes` from `noulVerdict` below that counts as unsure. A lens is in `add` when any chunk is a hit; in `unchecked` when none was a hit and at least one chunk was unsure, failed or not asked; neither otherwise. `add` never holds a name in `named`.
  - `authored` output `{ judge, generated: { file: string; reason: 'name' | 'marker' | 'judge' }[], authored: string[], unchecked: string[] }` over non-deleted files. `name`: base name `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Gemfile.lock`, `Cargo.lock`, `poetry.lock`, `composer.lock`, `go.sum`, `packages.lock.json`, or extension `.lock`. `marker`: the first 5 lines at `--root` contain `@generated` or `DO NOT EDIT`. The rest: one request each, `{ origin: AUTHORED_QUESTION }` over `authoredState(path, <first 40 lines at --root, or the hunk text when the file is missing>)`; confident `generated` goes to `generated` with reason `judge`, confident `authored` to `authored`, anything else to `unchecked`. `name` and `marker` cost no request.
  - `search` output `{ judge, lenses: Record<string, { flagged: { file: string; line: number; name: string | null }[]; unchecked: { file: string; line: number; name: string | null }[]; brief: string }> }`, one entry per `--lens` (at least one required, each a key of `lensFocus`, else exit 2 with the usage line). For each non-deleted file: the source at `--root`, `reviewUnits(path, source, <all added lines>)`; each unit's text cut into chunks of at most `REVIEW_CHUNK_CHARS` by lines; per chunk, the lenses in pairs, `focusQuestion(<focus>, unit.name === null ? 'change' : 'function')` over `unitState(path, unit.name, chunk)`. A unit is flagged for a lens when any chunk answers `yes`; unchecked when none answered `yes` and one was unsure or failed. `line` is the unit's `startLine`.
  - `brief` text, lines joined by `\n`: with flagged or unchecked units, `Judge search for <lens>: start with these functions, then review the whole diff as usual.`, then `- <file>:<line> <name or (changed lines)>` per flagged unit, then, when any, `Not checked by the judge; read these too:` and the same line form per unchecked unit; with neither, `Judge search for <lens>: no function flagged; review the whole diff as usual.`
  - At `log-only` the command asks and logs as at `enabled`, and returns `add: []`, `unchecked: []`, `generated: []`, `authored: []`, every lens `flagged: []`, `unchecked: []` and the no-function brief. With `judge` `none` or `invalid` it makes no request and returns the same empty form (`named` still filled).
  - At most `REVIEW_MAX_IN_FLIGHT` requests at once when `concurrencyOf()` is `concurrent`, one at a time when it is `sequential`; every request carries at most 2 questions; a request the run breaker stops (`circuit-open`) leaves its units or lenses unchecked.
  - One decision-log line per run: `event: 'review'`, `harness`: `--harness`, `session: null`, `cwd`: `--root`, `text`: the package's base name, `source: 'judge'` (or `judge-down` when every request failed), `action`: the subcommand, `answer`: `add=<names joined by ,>;unchecked=<names>` for `tripwires`, `generated=<count>;unchecked=<count>` for `authored`, `<lens>=<flagged count>/<unchecked count>` joined by `;` for `search`, `latencyMs`: the sum.

**Risks:** the command must never make a lens look unnecessary: it has no output that removes a lens, `unchecked` is separate from clean, and task 12's text keeps every named lens. A large branch diff makes many requests: chunks are bounded, at most four run at once, each within its budget, the run breaker stops a dead judge after three failures, and the controller runs the command once per review. A small false-positive rate per chunk adds up over a large diff: a chunk adds a lens only at `p >= 0.9`. Generated-file detection by name could hide an authored file named like a lock file; it only affects the branch-pass triggers (task 12), never a named lens.

**Testing:** unit tests for the parsers; process tests for the three subcommands against the fake server with fixture packages.

- [ ] `search` returns flagged functions with file, line and name, plus a brief block the controller can paste, for every requested lens.
- [ ] No judge means no request and empty results; `log-only` logs and returns empty results.
