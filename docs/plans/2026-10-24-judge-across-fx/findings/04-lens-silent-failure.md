The judge-failure path in `execute.before` is sound. A failed judge reaches `shellGuardOff` (line 440), nothing is stored, and `shellGuard` runs the code rules at line 205 on every shell call. The hard rules at line 194 run first and are not affected by the judge. The `catch {}` at line 181 is commented and deliberate, because stderr was already written, so I did not flag it.

1. [Important] `/development/fx/.worktrees/judge-across-fx/src/plugins/fx-opencode-v2.ts:116,434`: The judge can be skipped with no stderr line and no decision-log entry. Line 116 binds `guardShell` only if it is a function. When the export is missing but `guardShellCodeOnly` loaded, `shellGuardError` stays unset. The early return at line 434 then skips the judge on every shell call, and nothing records it. The same silent skip happens when `awaitsBefore()` is false. The design rule says a judge failure must show in the decision log, and here a permanently disabled judge looks the same as a judge that allowed everything. The code rules still run, so this is not a safety hole. The loss is that nobody can tell the judge is off.

2. [Important] `/development/fx/.worktrees/judge-across-fx/src/plugins/fx-opencode-v2.ts:439-440,172-181`: A judge failure is logged with only the message, capped at 200 characters, and no stack or cause. A judge timeout, a network error and a `TypeError` bug inside the judge all produce the same `guard-error` / `allow` entry. A typo that breaks the judge on every call looks like a flaky dependency, and the entry gives no way to tell them apart. The entry also records `text: ''`, so there is no way to match a failure to a command. This is a deliberate redaction choice (comment at lines 169-171). A call key or the command's length or hash would keep the redaction and make the entry traceable.

3. [Important] `/development/fx/.worktrees/judge-across-fx/src/plugins/fx-opencode-v2.ts:175-181,176-177`: The decision-log write is best-effort, so the stated rule can break silently. If `machinePaths` failed to load (line 167) or the append throws, the only trace is one stderr line from line 174. That line is not deduplicated, and a plugin host may not keep it. In that case the "must show in the decision log" rule has no durable record. The comment admits this ("the warning above is the trace"). This is accepted by design if stderr counts as a trace, but the path where the log never appears is not visible to the operator.

4. [Minor] `/development/fx/.worktrees/judge-across-fx/src/plugins/fx-opencode-v2.ts:229-232`: `remember` evicts the oldest stored decision once there are more than 200, with no log. If an evicted call later reaches `evaluate`, the judge's verdict is gone and only the code rules run. A judge `deny` or `ask` could turn into an allow with no trace. The cap exists for cancelled calls and should be rare, but the eviction should leave a line.
