Lens: silent-failure, 3 findings

1. [Important] `/development/fx/.worktrees/lean-review/hooks/fx-pretooluse.js:43-45`: `catch {}` around `require('../lib/dispatch-route')` discards the error and writes nothing. If the module is missing, has a syntax error, or has a bad require, `route` becomes `() => null` for the whole session. Every Agent dispatch then runs on the parent's model, including opus where `sonnet` was intended. Nothing in the output shows this, so the only symptom is a cost increase. Fail-open is the stated design, and I am not disputing it. What is lost is the signal that the feature is off. The git-guard load failure at line 32 writes the cause to stderr. This branch drops the cause, and lane-check at line 36 does the same. A test that covers only route's return values will not catch a hook that never loaded route.

2. [Important] `/development/fx/.worktrees/lean-review/hooks/fx-pretooluse.js:88-91`: `catch { result = null; }` covers the call to `route(ti)`. That is pure synchronous logic, so a throw there means a real bug, such as a `TypeError` from a malformed `ti.prompt`, and not an expected runtime condition. The handler is broad enough to hide typos and regressions in `lib/dispatch-route.js`, and it discards the exception object. The same code path can fail on every Agent call, and routing stays off with no trace. The comment at `lib/dispatch-route.js:6` says "the hook treats any throw as null" but nothing says the throw is recorded. The caller cannot tell "type not routable" from "routing crashed". It needs only a one-line stderr note with the error message. The fail-open outcome itself is fine.
