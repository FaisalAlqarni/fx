Lens: silent-failure, 2 findings

The never-throw contract holds, and the missing-file fallback (ENOENT) is a deliberate, commented and correct swallow. I did not flag it. The problem is that one catch treats "no file" and "a file the user wrote that I could not honor" as the same case.

1. [Important] /development/fx/.worktrees/lean-review/lib/preamble.js:65-67: the bare `catch { }` swallows any read or parse failure with no signal. A `.fx.json` that exists but has a trailing comma, a comment, a BOM or an unreadable mode (EACCES, EISDIR) is handled exactly like a missing file. If the owner wrote `{"companions": ""}` to turn the line off, or wrote a custom line, a typo elsewhere in the file makes the preamble silently inject the default line into every session and every subagent. Nothing logs or surfaces the failure. The owner sees the wrong behavior and has no hint that their override was dropped or why. The comment at line 67 says "no file, or not JSON" but the catch cannot tell those apart. ENOENT is expected and needs no signal. Parse errors and non-ENOENT read errors are a broken explicit override, and they are lost the same way. The catch also hides any future bug inside the try body, such as a typo in a destructure. The ADR and the task spec both record this fallback as intended, so I did not treat it as a defect. I flag it because nothing lets a human tell the two cases apart.

2. [Minor] /development/fx/.worktrees/lean-review/lib/preamble.js:66: any non-string `companions` value, such as `false`, `null` or `0`, silently yields the default line. `false` is the obvious thing to write to turn the line off. The user's intent is reversed and there is no signal. This is specified behavior ("non-string means the default"), but it is the same class of loss as finding 1 and is less likely to be noticed. Only the `""` form turns the line off.

The plans-block catch at line 104 is commented, deliberate and correct. The wider blast radius of both findings is that every harness and every subagent gets the wrong line, because the render path is shared.
