# 09: Stop evidence check on Claude Code and Codex

**Status:** ready-for-agent
**Blocked by:** 08
**Phase:** Core

**What to build:** when a Claude Code or Codex turn, or a subagent's turn, is about to end after editing files and no check has passed since the last edit, fx blocks the stop once with a reason that names the check to run. The agent then runs it or says plainly that it cannot. It never blocks twice in one turn: not when the harness says the stop hook already fired, and not when fx's own journal shows a block in this turn. A turn that edited only documentation is exempt. With a judge configured and a non-empty final message, one more question asks whether that message claims the work is verified; a clear "no" lifts the block. A missing or empty message keeps the block with no judge call. A down or unsure judge keeps it. A repo can switch the check off with `"hooks": { "stop_check": false }`.

**Interfaces:**
- Consumes: `journalKey`, `appendEvent`, `readJournal`, `currentTurn` (task 02); `readRepoConfig` (task 02); `checkHint` (task 08); `loadJudge`, `askJudge` (task 01); `OVERCLAIM_LIFT_MAX` (task 01); `redact`, `CAP_MESSAGE` (task 01); `logDecision` (task 01); test helpers (task 01).
- Produces in `src/lib/stop-check.ts`:
  - `DOC_EXTENSIONS = ['.md', '.mdx', '.txt', '.rst', '.adoc']`
  - `turnNeedsEvidence(turn: JournalEvent[]) -> boolean` (true when the turn has an `edit` event whose path does not end in a doc extension, and no `tool` event with `verified` true comes after the last such edit)
  - `decideStop(input: { harness: Harness, sessionId: string | null, agentId: string | null, cwd: string, stopHookActive: boolean, lastMessage: string | null, mode: 'block' | 'reminder' }, judge?: JudgeHandle) -> Promise<{ text: string | null }>` (journal key is `journalKey(sessionId, agentId)`; `null` when: no key, `stopCheck` off, `stopHookActive`, a `stop-block` event already in the turn, or `turnNeedsEvidence` false; otherwise asks the judge when one is ready and `lastMessage` is a non-empty string (red team I11: `null` or `""` keeps the block with no judge call), and lifts on an `overclaims` answer at most `OVERCLAIM_LIFT_MAX` with no escalation; on a block appends `stop-block` and logs `event: 'stop'`, `action: 'block'`; on a lift logs `action: 'lift'`; never rejects)
  - `OVERCLAIM_QUESTION: JudgeQuestion` = noul, instructions `The final message claims the work is finished, tested or verified.`; request state `{ final_message: <redacted, capped lastMessage, or "">, harness }`
- Produces: texts (`<hint>` is `checkHint(readRepoConfig(cwd).checks)`):
  - `mode: 'block'`: `[fx] This turn edited files and no check has passed since the last edit. Run <hint> and report the result before you finish. If you cannot run it, say so plainly.`
  - `mode: 'reminder'` (used by task 10): `[fx] The previous turn edited files and no check passed after the last edit. Run <hint> before you report that work as done.`
- Produces: Claude `Stop` and `SubagentStop`: on a block, stdout `JSON.stringify({ decision: "block", reason: text })`, exit 0; otherwise no output, exit 0. `SubagentStop` uses the subagent's `agent_id`; `Stop` uses no agent id. Codex: the same JSON on a block (Codex turns the reason into a continuation prompt); no output otherwise.

**Seam:** both hooks as processes driven through a whole turn (`UserPromptSubmit`, `PostToolUse` calls, then `Stop`), with a fake `/v1/systemone` server.
