# 06: Shell guard on opencode 1.x

**Status:** ready-for-agent
**Blocked by:** 05
**Phase:** Core

**What to build:** the opencode 1.x plugin runs the shell guard on every `bash` call the git guard allows. A deny refuses the call with its reason. opencode 1.x has no ask, so an ask also refuses, with a line telling the agent to confirm with the user and, after the user agrees in a new message, re-run with `# fx-ok: <reason>`; that stamp then gives a warned run. A judged deny retried within ten minutes stays denied. A warn lets the call run and prints the reason to stderr and the decision log. The judge never sees a prompt on opencode (the trust rule: fx cannot tell a user's prompt from a parent agent's prompt to a child session there). Each new user message marks a turn boundary in the session journal through `chat.message`. When a configured judge is down, the first request of each session carries the health line in its system text, and it is printed to stderr once.

**Interfaces:**
- Consumes: `guardShell` (task 03) with `harness: 'opencode'`, `sessionId` from the hook input's `sessionID`, `agentId: null`; `judgeHealth` (task 04); `journalKey`, `appendEvent` (task 02); `parseOpencodeToolEvent` (sub-project 1); test helpers (task 01).
- Produces, in `tool.execute.before` for `bash` after the git guard allows, `guardShell` with `harness: 'opencode'` (so a loop-guard repeat is a deny and an honoured stamp is a warn): allow returns; warn writes the reason to stderr (`console.error`) and returns; deny `throw new Error(reason)`; ask `throw new Error(reason + ' If the user agrees in a new message, add "# fx-ok: <reason>" to the command and run it again.')`.
- Produces: `chat.message` appends `{ kind: 'prompt', text: null }` to `journalKey(sessionID)`. Before writing it, read opencode 1.18.25's `chat.message` signature (the binary or the matching source tag, the way the header comment of this plugin records its other measurements) and record the field holding the session id in that header comment; when no session id can be read, the hook does nothing.
- Produces: the health result is computed once per plugin construction (`judgeHealth({ harness: 'opencode', cwd, sessionId: null })`) and, when non-null, printed to stderr once; `experimental.chat.system.transform` awaits it and pushes the line after the preamble once per `input.sessionID` (a call without a session id pushes nothing) (red team M22).
- Produces: `lib/shell-guard.js` and `lib/judge-health.js` load through `createRequire` inside `try`, beside today's guarded loads. A failed shell-guard load leaves `bash` calls to the git guard alone and pushes `[fx] shell guard off: <message>` into the system text once.
