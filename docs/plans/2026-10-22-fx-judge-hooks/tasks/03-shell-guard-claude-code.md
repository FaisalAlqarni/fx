# 03: Shell guard on Claude Code

**Status:** ready-for-agent
**Blocked by:** 02
**Phase:** MVP

**What to build:** on Claude Code, every `Bash` call the git guard allows now passes the shell guard. Catastrophic commands are refused outright, wherever they sit in a chain, with a reason and no way around it: no stamp, no repo switch. A word that only appears as an argument or inside a heredoc body is not refused. Plain read-only commands and the repo's own `.fx.json` check and setup commands run with no judge call and no log line. Every other command goes to the judge when one is configured: one choice question (ask, run, deny), whose answer becomes allow, Claude Code's own ask prompt, or a deny; an unsure judge becomes ask. With no judge, a judge that is down or slow, or a repo that set `"hooks": { "shell_judge": false }`, grey commands run and the decision is logged. A `# fx-ok: <reason>` stamp counts only after the user has written a new prompt since the refusal, and then it turns a judged deny into ask; it never skips an ask. A judged deny retried within ten minutes becomes ask, never allow. The judge sees only the command (comments removed, redacted), the directory name, the harness and the user's latest prompt. If the guard itself breaks, at load or later, the call runs and the user sees `[fx] shell guard off`.

- Produces in `src/lib/shell-guard.ts`:
  - `classifyShell(command: string) -> { kind: 'hard-deny', rule: string, reason: string } | { kind: 'read-only' } | { kind: 'grey' }`
  - `stripComments(command: string) -> string` (removes every `#` that starts a word outside single or double quotes, through the end of its line; heredoc bodies untouched)
  - `normalizeCommand(command: string) -> string` (`stripComments`, then trimmed, runs of whitespace collapsed to one space, then `redact(…, CAP_COMMAND)`; the form stored in the journal and compared by the loop guard and the stamp rule)
  - `overrideReason(command: string) -> string | null` (text after an unquoted `# fx-ok:`, trimmed; `null` when absent or empty)
  - `guardShell(input: { command: string, cwd: string, harness: Harness, sessionId: string | null, agentId: string | null, now: number, judgeSupported?: boolean }, judge?: JudgeHandle) -> Promise<GuardDecision>` (never rejects; `judge` defaults to `loadJudge()`; `judgeSupported: false` replaces the judge step with allow, source `judge-unsupported`; it logs, and appends `deny` and `ask` events to the root key `journalKey(sessionId)`, itself; the returned action is already the one for `harness`, see below)
- Produces in `src/lib/evidence.ts` (red team I10, one rule):
  - `isRepoCommand(command: string, template: string | null) -> boolean`: `null` is false; a template with no `{` matches a normalized command equal to it or starting with it plus a space; a template with `{` matches on its text before the first `{`, trimmed, and only when that prefix has at least two space-separated words or its first word contains `/`.
  - `isCheckCommand(command: string, checks: CheckCommands) -> boolean`: `isRepoCommand` against `test_one`, `test_scope`, `test_all` or `lint` (never `setup`).
- Produces in `src/lib/guard-output.ts`: `claudeGuardOutput(d: GuardDecision) -> { stdout: string, stderr: string, exitCode: 0 | 2 }`:
  - allow: `{ stdout: "", stderr: "", exitCode: 0 }`
  - warn: stdout `JSON.stringify({ systemMessage: reason, hookSpecificOutput: { hookEventName: "PreToolUse", additionalContext: reason } })`, exit 0
  - ask: stdout `JSON.stringify({ hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "ask", permissionDecisionReason: reason } })`, exit 0
  - deny: stderr `reason + "\n"`, exit 2

**Guard order inside `guardShell`:**
1. `classifyShell` hard rule: deny, `hard-rule`. Nothing below can change it.
2. `read-only`: allow, not logged. Then the repo-command allowlist: `isCheckCommand(cmd, checks)` or `isRepoCommand(cmd, checks.setup)`, and the text after the matched part holds none of `;`, `&`, `|`, `>`, `<`, `` ` ``, `$(...)`, newline: allow, `repo-command`, not logged.
3. Loop guard: a `deny` event for the same normalized command in the root journal within `LOOP_GUARD_MS`, with no honoured stamp: no judge call; ask on `claude-code` and `opencode-v2`, deny on `codex` and `opencode`; source `loop-guard`.
4. `shellJudge` off in `readRepoConfig(cwd)`: allow, `switched-off`, logged. `judgeSupported: false`: allow, `judge-unsupported`, logged.
5. Judge with `GUARD_QUESTION`; state `{ command: redact(stripComments(cmd), CAP_COMMAND), cwd: <base name>, harness }` plus `user_request: lastUserPrompt(sessionId)` when non-null (the root session id, also for a subagent's call). Unavailable: allow, `no-judge` or `judge-down`. Policy: `run` and no escalation: allow, `judge`; `deny` with top at least `DENY_MIN_TOP` and gap at least `DENY_MIN_GAP`: deny, `judge`; anything else: ask, `judge` or `judge-unsure`.
6. Stamp: `overrideReason(cmd)` non-null and the root journal holds a `prompt` event after the most recent `deny` or `ask` event for this normalized command: a judged deny or ask becomes ask on `claude-code` and `opencode-v2` and warn on `codex` and `opencode`; a judged allow stays allow; source `override`, the reason logged in `override`. A stamp with no such prompt is ignored. A stamp never changes steps 1 to 4.
7. Every judged `deny` appends a `deny` event and every judged `ask` an `ask` event (normalized command).

**Exact reason texts** (`<p>` is the probability with two decimals):
- hard denial: `[fx] refused: <rule text> This rule has no override.` Rule texts: `rm-root` "rm -r on a root, home or system directory cannot be undone."; `disk` "formatting or overwriting a disk destroys its data."; `fork-bomb` "a fork bomb exhausts the machine."; `perms-root` "recursive chmod or chown on a root or home directory breaks the system."; `pipe-to-shell` "running a download as a shell script runs code nobody has read."; `power` "shutting down or rebooting ends every session on this machine."; `win-wipe` "recursive deletion of a drive root or home directory cannot be undone."
- judge deny: `[fx] shell guard denied: the judge answered deny (p=<p>). If the user asks for exactly this in a new message, add "# fx-ok: <reason>" to the command and run it again.`
- ask from an ask answer: `[fx] shell guard asks: the judge answered ask (p=<p>). Confirm with the user before running it.`
- ask from an escalation: same form with `the judge was unsure (<escalate reason>)`.
- ask from a weak deny: same form with `the judge answered deny without enough confidence (p=<p>)`.
- loop-guard ask: `[fx] shell guard asks: this command was denied less than 10 minutes ago. Confirm with the user before running it.`; loop-guard deny (Codex, opencode 1.x): `[fx] shell guard denied: this command was denied less than 10 minutes ago. Ask the user in a new message before trying it again.`
- override (ask or warn): `[fx] shell guard: "# fx-ok: <stamp reason>" after a new user message; the judge answered <answer> (p=<p>). Confirm with the user before running it.`
- guard failure: `[fx] shell guard off: <message>`.

**Hard rules, the full list** (red team I4, I5). Each segment from `splitSegments(stripHeredocs(cmd))`, each `expandShellC` argument recursively, and the pipeline and process-substitution forms below are checked; the program is the first word after `VAR=value` assignments and the wrappers `sudo`, `env`, `command`, `nice`, `nohup`, `time`, `timeout` (and its duration), `exec`, compared by base name (`/bin/rm` is `rm`):
- `rm-root`: program `rm` with a recursive flag (a `-` cluster containing `r` or `R`, or `--recursive`), any other flags, and an argument (quotes removed) among `/`, `/*`, `~`, `~/`, `~/*`, `$HOME`, `${HOME}`, `$HOME/`, `$HOME/*`, `${HOME}/`, `${HOME}/*`, `/home/<name>`, `/Users/<name>` (each with or without `/` or `/*`), or one of `/bin`, `/boot`, `/dev`, `/etc`, `/home`, `/lib`, `/lib64`, `/opt`, `/proc`, `/root`, `/sbin`, `/srv`, `/sys`, `/usr`, `/var`, `/Users`, `/System`, `/Library`, `/Applications`, `/private` (each with or without `/` or `/*`).
- `disk`: program `mkfs` or `mkfs.<fs>`; `dd` with an `of=/dev/` argument; a `>` or `>>` redirection whose target starts `/dev/sd`, `/dev/nvme`, `/dev/hd`, `/dev/vd`, `/dev/disk` or `/dev/mmcblk`.
- `fork-bomb`: the text `:(){` with optional spaces, or a function that pipes into itself and backgrounds (`f(){ f|f& };f` shape).
- `perms-root`: `chmod` or `chown` with `-R` or `--recursive` and a target from the `rm-root` root and home spellings.
- `pipe-to-shell`: a segment whose program is `curl`, `wget`, `iwr`, `irm`, `Invoke-WebRequest` or `Invoke-RestMethod`, followed by `|` (not `||`) into a segment whose program (after `sudo`) is `sh`, `bash`, `zsh`, `dash`, `iex` or `Invoke-Expression`; a shell program with a process-substitution argument `<(...)` whose content's program is a downloader; a shell's `-c` argument containing `$(...)` or backticks whose content's program is a downloader.
- `power`: program `shutdown`, `reboot`, `halt` or `poweroff`.
- `win-wipe`: `format` followed by a drive letter and `:`; `Remove-Item` (or `rm`, `del`, `ri` as PowerShell aliases) with `-Recurse` and a target `<drive>:\`, `<drive>:\*`, `~`, `$HOME` or `$env:USERPROFILE`; `rd` or `rmdir` with `/s` and a drive root or `%USERPROFILE%`; `del` with `/s` and a drive root.

**Allowlist detail** (red team I6): programs and per-program refused flags as design decision 5 step 2 lists; for `git`, any token starting `-` between `git` and the subcommand makes the command grey; secret paths as design decision 5 step 2 lists, matched as substrings of any argument.

**Fail open in the hook** (red team I8): `fx-pretooluse` keeps today's deny-on-crash handler until the git guard has allowed. Then it removes it and installs `uncaughtException` and `unhandledRejection` handlers that write the guard-failure warn output and exit 0. It writes its output and calls `process.exit` in the write callback, on every path.

## Acceptance criteria
- [ ] Every hard-rule spelling in the Tests field is refused with its exact reason, and no stamp, repo switch or loop guard changes that.

- [ ] A guard failure, synchronous or asynchronous, lets the call through with `[fx] shell guard off`, and the git guard still refuses.
