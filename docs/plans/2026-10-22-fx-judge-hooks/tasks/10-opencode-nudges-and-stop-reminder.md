# 10: Nudges and Stop reminder on opencode

**Status:** ready-for-agent
**Blocked by:** 09
**Phase:** Core

**What to build:** on opencode 1.x and 2.x, every tool call is recorded in the session journal the way Claude Code and Codex record it, so the same three stuck-loop signals fire. Neither major can block a turn from ending, so the Stop check runs at the next user prompt over the turn that just ended. A missing-evidence result becomes a reminder. Nudges and reminders are queued in the plugin's memory per session and pushed once into the system text of that session's next model request. Subagent child sessions get no further user prompt, so the Stop reminder does not cover them.

**Design:** Implementation Decisions > 7; Implementation Decisions > 8; Implementation Decisions > 4; Implementation Decisions > 12

**Files:**

- Modify: `src/plugins/fx-opencode-v2.ts` (`execute.after`; the `prompt` hook runs the turn-end check before marking the boundary; the `context` hook pushes queued lines)

**Interfaces:**
- Consumes: `recordToolResult` (task 08); `decideStop` with `mode: 'reminder'`, `stopHookActive: false`, `lastMessage: null`, `agentId: null` (task 09); `classifyTool`, `editedPaths` (task 08); `journalKey`, `appendEvent` (task 02); test helpers (task 01).
- Produces: one in-memory queue per plugin instance, `Map<sessionId, string[]>`. `recordToolResult`'s non-null line and `decideStop`'s non-null text are pushed onto the session's queue; the system transform (1.x, when `input.sessionID` is a string) or the `context` hook (2.x) pushes each queued line as its own system entry after the preamble and the health line, then empties that session's queue.
- Produces: the turn-end order at a new user prompt: first `decideStop` over the journal as it stands (the turn that just ended), then `appendEvent(prompt, text null)`.
- Produces: outcome per major. Before writing it, read the 1.18.25 `tool.execute.after` output shape and the 2.0.18 `execute.after` event shape (the same sources tasks 06 and 07 used) and record in the plugin header comments where the output text and any exit status live. A numeric exit status gives `ok` for 0 and `fail` otherwise; no exit status gives `unknown`. 2.x already sees a refused call in `execute.after` with `status: "error"` (probe finding): that is `fail`.
- Produces: `harness` is `opencode` (1.x) and `opencode-v2` (2.x); nudge lines name the lane `fx-debug`.

**Seam:** the plugins called in-process through whole turns, as in tasks 06 and 07.

**Tests:**
- opencode 1.x, session `s1`, under the scratch environment:
  - three `tool.execute.after` calls for `bash` `npm test` with a failing exit status: the next `experimental.chat.system.transform` call for `s1` pushes, after the preamble, `` [fx] `npm test` has failed 3 times this turn. Stop retrying and invoke fx-debug to find the cause. ``; the call after that pushes no such line.
  - `chat.message` (turn start), `tool.execute.after` for `edit` of `a.ts`, then `chat.message` again: the next transform for `s1` pushes `[fx] The previous turn edited files and no check passed after the last edit. Run the project's tests before you report that work as done.` once.
  - the same with `<cwd>/.fx.json` `{"test_all":"make test"}` and a `bash` `make test` call with exit status 0 after the edit: no reminder.
  - a transform call whose `input.sessionID` is undefined: no queued line is pushed and the queue is kept.
- opencode 2.x, session `s1`, fake `ctx`:
  - twelve `execute.after` events for `read`: the next `context` call for `s1` pushes the passive-stall line naming `fx-debug`.
  - `prompt`, `execute.after` for `edit` of `a.ts`, then `prompt` again: the next `context` call pushes the reminder text once.
  - `.fx.json` `{"hooks":{"stop_check":false}}`: no reminder.
- Both majors: a session with no session id in the event: nothing recorded, nothing pushed.
- Existing: every opencode gate from tasks 06 and 07 passes; `bash tests/install/run.sh opencode`, `bash tests/install/run.sh opencode-v2`, and both free conformance runs pass.

**Risks:** a 1.x transform call site without `sessionID` (the plugin header records one) must not drop or misdeliver queued lines. The queue lives in memory, so a restarted opencode loses undelivered lines: accepted, it is advice. Every 2.x hook body catches.

**Idempotency:** none needed.

**Testing:** in-process plugin gate through whole turns, existing opencode gates, install runs and free conformance through `scripts/check-all`.
