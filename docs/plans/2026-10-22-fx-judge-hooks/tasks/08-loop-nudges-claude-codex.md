# 08: Stuck-loop nudges on Claude Code and Codex

**Status:** ready-for-agent
**Blocked by:** 07
**Phase:** Core

**What to build:** after every tool call on Claude Code and Codex, fx records what kind of call it was (edit, read, shell, other), its outcome, and whether it verified the work (a repo check command that succeeded, or a test runner's pass summary in the output). When the agent runs the same failing command a third time in a turn, reads twelve times in a row with no edit, or makes ten edits with no check, the model gets one short line pointing at fx-debug, once per signal per turn. It never blocks. A repo can switch the lines off with `"hooks": { "loop_nudge": false }`; the recording continues, because the Stop check (task 09) reads it.

**Interfaces:**
- Consumes: `isRepoCommand`, `isCheckCommand` (task 03); `READ_ONLY_AGENTS` (`lib/plant-roles`); `journalKey`, `appendEvent`, `readJournal`, `currentTurn` (task 02); `readRepoConfig`, `CheckCommands` (task 02); `classifyShell`, `normalizeCommand` (task 03); `REPEAT_FAILURES`, `PASSIVE_READS`, `UNVERIFIED_EDITS` (task 01); `logDecision` (task 01); test helpers (task 01).
- Produces in `src/lib/tool-events.ts`:
  - `classifyTool(harness: Harness, toolName: string, command: string | null) -> ToolKind`: `edit` for Claude `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, Codex `apply_patch`, opencode `edit`, `write`, `apply_patch`; `read` for Claude `Read`, `Grep`, `Glob`, opencode `read`, `grep`, `glob`, `list`, and any shell call whose command `classifyShell` calls `read-only`; `shell` for any other shell call (Claude `Bash`, Codex `Bash`/`exec_command`, opencode `bash`, opencode 2.x `shell`); `other` otherwise.
  - `toolOutcomeAndOutput(harness: Harness, event: string, toolResponse: unknown) -> { outcome: 'ok' | 'fail' | 'unknown', output: string }`: Claude `PostToolUse` is `ok`, `PostToolUseFailure` is `fail`, output from `tool_response.stdout` and `.stderr` (strings, joined with `\n`) or the failure's `error` string; Codex reads a numeric `exit_code` or `exitCode` field, or a `^Exit code: (\d+)` line in a string response (0 is `ok`, other is `fail`), otherwise `unknown`, output the string response or those fields; output is the last 4 KB.
  - `editedPaths(harness: Harness, toolName: string, toolInput: unknown, cwd: string) -> string[]` (Claude `file_path`/`notebook_path`; Codex and opencode `apply_patch` through `extractPatchPaths`; opencode `filePath`).
- Produces in `src/lib/evidence.ts`:
  - `hasPassSummary(output: string) -> boolean` (the design's patterns over the last 4 KB; a count must be at least 1, so `0 passed` is false)
  - `countsAsVerification(kind: ToolKind, command: string | null, outcome: 'ok' | 'fail' | 'unknown', output: string, checks: CheckCommands) -> boolean` (red team I9: false unless `kind` is `shell`; true when `isCheckCommand` matches, the outcome is `ok`, and nothing but arguments follows the matched part; otherwise true only when the program of the command's first segment is not `echo`, `printf`, `cat`, `grep`, `rg`, `head`, `tail`, `sed` or `awk` and `hasPassSummary(output)`; a check command followed by `|`, `||` or `;` therefore verifies only through a pass summary)

  - `checkHint(checks: CheckCommands) -> string` (`` `<test_scope>` `` when set, else `` `<test_all>` ``, else `the project's tests`)
- Produces in `src/lib/loop-tracker.ts`:
  - `checkSignals(turn: JournalEvent[]) -> NudgeSignal | null` (the first signal, in the order `repeat-failure`, `unverified-writes`, `passive-stall`, that has reached its threshold and has no `nudge` event for it in `turn`)
  - `recordToolResult(input: { harness: Harness, sessionId: string | null, agentId: string | null, cwd: string, toolName: string, toolInput: unknown, command: string | null, outcome: 'ok' | 'fail' | 'unknown', output: string }) -> string | null` (appends one `tool` event with `verified = countsAsVerification(kind, command, outcome, output, readRepoConfig(cwd).checks)`, then one `edit` event per edited path; then, unless `loopNudge` is off or the journal's first `prompt` event names an `agentType` in `READ_ONLY_AGENTS` (`lib/plant-roles`; red team I17), runs `checkSignals` (with `passive-stall` skipped when `agentId` is non-null) on the current turn and, on a signal, appends a `nudge` event, logs `event: 'nudge'`, and returns the line; no session id: returns `null` and writes nothing; never throws)
- Produces: nudge lines, exactly (`<lane>` is `laneAddress(harness, 'fx-debug')`: `fx:fx-debug` on Claude Code, `$fx:fx-debug` on Codex, `fx-debug` on opencode; `<cmd>` is the normalized command cut to 80 characters):
  - `repeat-failure`: `` [fx] `<cmd>` has failed 3 times this turn. Stop retrying and invoke <lane> to find the cause. ``
  - `passive-stall`: `[fx] 12 reads in a row with no edit. If you are going in circles, invoke <lane>; otherwise say what you are looking for.`
  - `unverified-writes`: `[fx] 10 edits since the last passing check. Run <checkHint> now; if it fails, invoke <lane>.`
- Produces: signal counting within the current turn. `repeat-failure`: three `tool` events with outcome `fail` and the same `command`, with no `edit` event between the first and the third of them (red team I17). `passive-stall`: the last twelve `tool` events are all `read` with no `edit` event after the first of them. `unverified-writes`: ten `edit` events after the last `tool` event with `verified` true (or the turn start).
- Produces: Claude output on a nudge: `JSON.stringify({ hookSpecificOutput: { hookEventName: <"PostToolUse" | "PostToolUseFailure">, additionalContext: line } })`, exit 0; no nudge: no output, exit 0. Codex: the same with `"PostToolUse"`. `fx-turn` and `fx-codex` never exit 2 on these events.

A PostToolUse hook runs on every tool call: it must exit within the 5 s timeout and never call the judge.

**Idempotency:** the journal is append-only; tests use scratch state.
