# 05: Shell guard and turn on Codex

**Status:** ready-for-agent
**Blocked by:** 04
**Phase:** Core

**What to build:** Codex gets the same shell guard as Claude Code, through the existing `fx-codex` hook. User prompts are recorded at a new `UserPromptSubmit` registration, so the judge sees the user's own words there too. Because Codex fails a hook run that returns ask and lets the call through anyway, an ask becomes a run with a visible warning: the user sees it as a `systemMessage` and the model as added context. Deny keeps today's exit 2 form. A loop-guard repeat stays a deny on Codex, and an honoured stamp gives a warned run (Codex has no ask). A `UserPromptSubmit` inside a spawned subagent carries the parent's dispatch text, so it only starts that subagent's turn. The read-only agent check and the git guard still answer first, a crash after the git guard has allowed fails open, the hook prints the preamble only for SessionStart and SubagentStart, and every new output key is pinned in the Codex output gate before the hook prints it.

**Interfaces:**
- Consumes: `guardShell`, `GuardDecision` (task 03); `journalKey`, `appendEvent` (task 02); `redact`, `CAP_PROMPT` (task 01); `parseCodexHookInput` (sub-project 1); test helpers (task 01).
- Produces: `codexGuardOutput(d: GuardDecision) -> { stdout: string, stderr: string, exitCode: 0 | 2 }`:
  - allow: empty, exit 0
  - warn and ask: stdout `JSON.stringify({ systemMessage: reason, hookSpecificOutput: { hookEventName: "PreToolUse", additionalContext: reason } })`, exit 0 (an ask keeps its ask reason text)
  - deny: stderr `reason + "\n"`, exit 2
- Produces: the Codex shell tool is `Bash` with a string `tool_input.command` (`exec_command` arrives under that name and shape; red team M21); anything else is no command (today's `if (!command) exit 0` path).
- Produces: `guardShell` called with `harness: 'codex'`, so a loop-guard repeat is a deny and an honoured stamp is a warn (task 03 step list).
- Produces: after the git guard allows, the deny-on-crash handler is replaced by `uncaughtException` and `unhandledRejection` handlers that print the `codexGuardOutput` warn form of `[fx] shell guard off: <message>` and exit 0; every path ends in `process.exit` from the write callback (red team I8).
- Produces: an event that is neither `SessionStart` nor `SubagentStart` and that no branch routes prints nothing and exits 0 (today it falls through to the preamble; red team M23).
- Produces: `UserPromptSubmit` on Codex: a prompt starting with `[fx] ` is ignored; with an `agent_id` it appends `{ kind: 'prompt', text: null, agentType: <agent_type or null> }` to `journalKey(session_id, agent_id)` only (red team C3); otherwise it appends `{ kind: 'prompt', text: redact(prompt, CAP_PROMPT) }` to `journalKey(session_id)`. It prints nothing, exits 0, never exits 2.
- Produces: Codex `SubagentStart` appends `{ kind: 'prompt', text: null, agentType: <agent_type or null> }` to `journalKey(session_id, agent_id)` beside today's identity record; its printed output is unchanged.
- Produces: root `hooks.json` gains `"UserPromptSubmit": [{ "hooks": [{ "type": "command", "command": "node \"${CLAUDE_PLUGIN_ROOT}/hooks/fx-codex.js\"" }] }]` (no timeout, as the other Codex entries).
- Produces in the Codex output gate: PreToolUse top-level keys `hookSpecificOutput` and `systemMessage`, inner keys unchanged (`additionalContext` is already allowed); `UserPromptSubmit` prints nothing. The gate's comment cites https://learn.chatgpt.com/docs/hooks ("PreToolUse and PermissionRequest support only systemMessage"; "Add context: hookSpecificOutput.additionalContext").
