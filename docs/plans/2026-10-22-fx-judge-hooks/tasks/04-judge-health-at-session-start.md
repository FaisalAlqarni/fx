# 04: Judge health line at session start

**Status:** ready-for-agent
**Blocked by:** 03
**Phase:** Core

**What to build:** when a user has a judge config and the judge cannot answer, or the config is invalid, a Claude Code or Codex session opens with one line saying so, shown to the user and to the model; the guard keeps running on code rules. A healthy judge, or no config at all, adds nothing, and a session's start output stays byte-identical to today. The same SessionStart also deletes session journals untouched for seven days. Subagent starts never probe.

**Design:** Implementation Decisions > 9; Implementation Decisions > 3

**Files:**
- Create: `src/lib/judge-health.ts`, `src/lib/judge-health.test.ts`
- Create: `src/tests/gates/judge-health.test.ts`
- Modify: `src/hooks/fx-context.ts` (SessionStart: health line and journal prune)
- Modify: `src/hooks/fx-codex.ts` (SessionStart: the same)
- Modify: `src/tests/gates/codex-hook-output.test.ts`, `src/tests/gates/codex-manifest.test.ts` and any other test that spawns `hooks/fx-codex.js` (find them with `grep -rln fx-codex src/tests src/lib`): run it under `scratchHookEnv()`, expected values unchanged

**Interfaces:**
- Consumes: `loadJudge`, `askJudge`, `machinePaths` (task 01); `logDecision` (task 01); `pruneJournals` (task 02); test helpers (task 01).
- Produces: `judgeHealth(input: { harness: Harness, cwd: string, sessionId: string | null }, judge?: JudgeHandle) -> Promise<string | null>` (never rejects; `none` gives `null` with no network call; a `ready` judge is asked one `noul` question named `probe`, the same question `judge-cli check` asks; success gives `null`; every non-null result is also logged with `event: 'health'`):
  - invalid config: `[fx] judge config <judgeConfig path> is invalid (<reason>): the shell guard and Stop check run on code rules only.`
  - unavailable: `[fx] judge at <base_url> is unavailable (<reason>): the shell guard and Stop check run on code rules only.` where `<reason>` is the `UnavailableReason`.
- Produces: Claude Code SessionStart with a health line: `additionalContext` is the rendered preamble with `trimEnd()`, a blank line, the health line and `\n`; top-level `systemMessage` is the health line. Without one: today's output, byte for byte.
- Produces: on Codex the health line gains ` New fx hook events need trusting once in /hooks.` at its end (red team M23: Codex skips an event until the user trusts it, and fx cannot read that state, ADR 0024).
- Produces: Codex SessionStart: the role-planting notice (today) and the health line, in that order, each appended to `additionalContext` as today's notice is, and `systemMessage` holding the present lines joined with `\n`. With neither: today's output.

**Seam:** both hooks as processes for SessionStart and SubagentStart.

**Tests:**
- Unit `judgeHealth`: handle `none`: `null`; handle `invalid` with reason `judge.json is not valid JSON` and the path `/c/fx/judge.json`: the invalid line with that path and reason; ready judge answering `probe` 0.9 (fake server): `null`; server status 500: line ending `is unavailable (http-500): the shell guard and Stop check run on code rules only.`
- Process, Claude `fx-context`:
  - SessionStart with no `judge.json`: stdout byte-identical to the golden gate's SessionStart expected output;
  - SessionStart with `judge.json` `{"model":"m"}`: `systemMessage` equal to `[fx] judge config <XDG_CONFIG_HOME>/fx/judge.json is invalid (base_url must be a non-empty string): the shell guard and Stop check run on code rules only.` and `additionalContext` ending with that line plus `\n`;
  - SessionStart with a fake server delaying 3,000 ms: `systemMessage` contains `is unavailable (timeout)`, the process finishes in under 2,500 ms, one decision-log entry with `event` `health`;
  - SessionStart with a fake server answering 0.9: no `systemMessage` key, `additionalContext` equal to the golden text, one request recorded;
  - SubagentStart with a dead judge (`base_url` pointing at a closed port): stdout equal to the golden SubagentStart output, zero requests;
  - SessionStart with `<XDG_STATE_HOME>/fx/sessions/old.jsonl` set to mtime 8 days ago and `new.jsonl` to 1 day ago: afterwards `old.jsonl` is gone and `new.jsonl` remains.
- Process, `fx-codex` (with `CODEX_HOME` set to a scratch directory, as `codex-hook-output` does):
  - SessionStart with no `judge.json`: output equal to the golden gate's Codex SessionStart output;
  - SessionStart with an invalid config, on a run that also plants roles: `systemMessage` is the planting notice, `\n`, then the health line ending ` New fx hook events need trusting once in /hooks.`; `additionalContext` ends with both, notice first;
  - `node tests/gates/codex-hook-output.test.js` passes unchanged (both keys are already allowed on SessionStart).

**Risks:** a probe adds up to 1.5 s to session start when the judge is configured and dead; Claude Code's SessionStart entry has a 5 s timeout, so the hook must not await anything else slow. The golden gate's SessionStart fixtures were recorded with no `judge.json`; they must not change.

**Idempotency:** the prune deletes only `*.jsonl` older than seven days inside fx's own `sessions/` directory.

**Testing:** unit, process gate, golden and Codex output gates, `scripts/check-all`.

## Acceptance criteria
- [ ] A configured but dead judge produces exactly one line at SessionStart on Claude Code and Codex, visible to the user.
- [ ] No config and a healthy judge both leave SessionStart output byte-identical to the golden fixtures.
- [ ] SubagentStart never probes.
- [ ] `scripts/check-all` prints `ALL GREEN`.
