# 11: Judge setup in fx-setup and user docs

**Status:** ready-for-agent
**Blocked by:** 10
**Phase:** Polish

**What to build:** a user running fx-setup is told that fx's guard, Stop check and nudges already work with no judge, and is offered an optional judge for this machine, following the owner's measurement: Nimble 9B on Ollama (tested on 0.40.7, the same setup on Windows, macOS and Linux) or Kev-4B (most accurate, needs Python and a GPU), Rizzo Flow (llama.cpp, all three OSes), `d1:3b` only as a listed alternative with its caveats, or a remote judge with a plain warning that commands and final messages are then sent to that service; any non-loopback address counts as remote. The user's choice is written through `node <FX>/lib/judge-cli.js write`, which validates it, takes a key only from standard input or a named environment variable, writes the per-OS file with mode `0600`, and then `check` reports whether it answers. fx-setup documents the `.fx.json` `hooks` switches. README and INSTALL describe the new hooks, that no judge is needed, the per-OS paths, the repo switches, which shells honour the stamp, and that Codex users re-trust fx's hooks after updating. The live conformance rows for these hooks belong to sub-project 4's task 14, not here.

**Interfaces:**
- Consumes: `parseJudgeConfig`, `machinePaths`, the `check` subcommand (task 01).
- Produces: `node lib/judge-cli.js write --base-url <url> --model <id> [--api-key-stdin | --api-key-env <NAME>] [--insecure-http]` (red team I15: never a key in the arguments): `--api-key-stdin` reads the key as the first line of standard input, trimmed; `--api-key-env <NAME>` reads it from that environment variable, and an unset or empty variable prints `judge: invalid: environment variable <NAME> is empty` and exits 1. It builds `{ base_url, model, api_key?, insecure_http? }` and validates it with `parseJudgeConfig`; invalid prints `judge: invalid: <reason>` to stderr and exits 1 with no file written; valid creates the config directory, writes the file (two-space JSON, trailing newline), sets mode `0600` on POSIX, prints `judge: wrote <path>`, and, when `isLoopbackUrl(base_url)` is false, a second line `judge: remote: grey shell commands and Stop final messages (redacted) will be sent to <host>`; exit 0. Any argument starting `--api-key=` or the bare `--api-key` prints `judge: refusing a key on the command line; use --api-key-stdin or --api-key-env` and exits 2. Missing `--base-url` or `--model` prints `usage: judge-cli path|check|write --base-url <url> --model <id> [--api-key-stdin | --api-key-env <NAME>] [--insecure-http]` to stderr and exits 2; the plain usage line of task 01 becomes this one.
- Produces: the fx-setup section tells the agent to: run `node "<FX>/lib/judge-cli.js" check` first and report its line; when the result is `judge: none`, offer the options above through the host's question tool with "no judge" as the first, default option and Nimble 9B or Kev-4B as the recommended judges (red team M26); `d1:3b` is listed last among the local options with the note that it let `cat .env` run in the owner's measurement and that its LFM licence has terms to read; Nimble's licence is noted as conflicting between its Ollama page (Apache-2.0) and its model card (CC BY-NC); for a local choice, give the install steps for the user's OS (Ollama, tested on 0.40.7: install, `ollama pull nimble:9b`, base URL `http://127.0.0.1:11434`; Kev: `uv run --extra serve python -m kev.serve --run jaredpalmer/kev-4b --port 8009`, base URL `http://127.0.0.1:8009`; Rizzo Flow: `rizzo serve`, base URL `http://127.0.0.1:8017`), never run an install itself, and write the config only after the user confirms the server runs; for a remote choice (hosted Jev at `https://api.typesafe.ai`, or OpenRouter, whose `/v1/systemone` path is unverified), state that every grey shell command and every Stop final message (redacted) is sent to that service, and have the user run `write` themselves with `--api-key-stdin` or `--api-key-env`, never pasting the key into the chat; then run `check` and report it. `<FX>` is resolved the way section 6 resolves it: the directory this lane was loaded from, never a path read from the repository.
- Produces: the `.fx.json` table row: `hooks` | Optional. `{ "shell_judge": false, "stop_check": false, "loop_nudge": false }`: `shell_judge` turns off only the shell guard's judge step (its hard rules and allowlist always run), the other two turn off the Stop check and the nudges; each defaults to on; read from the repository's top level. The git guard and lane check are not switchable.
