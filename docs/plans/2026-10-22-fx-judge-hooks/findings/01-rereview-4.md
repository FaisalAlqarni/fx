### New breakage

#### Important

1. `src/lib/redact.ts:130` · `redact` deletes every backslash-newline before the rules run, without checking whether the backslash is itself escaped or sits inside quotes or a quoted heredoc. The shell treats `\\` then a newline as an escaped backslash and a command break, so two commands become one in the text the judge sees. `echo x \\` then `echo SECOND-RAN` on the next line: bash prints `x \` and then runs the second command, and `redact` gives `echo x \echo SECOND-RAN`, a single echo. So `echo x \\` followed by `rm -rf ~` reaches the judge as `echo x \rm -rf ~`. A quoted heredoc does the same: a body line `x\` followed by `EOF` and then a command becomes `xEOF`, which moves every later command into the heredoc body in the judge's view. `src/lib/shell-guard.ts:259` sends this text to the judge as `command`. At 95f238a the text was left unchanged. The same rewrite also runs on prompts and messages (`src/lib/judge.ts:58`, `src/lib/journal.ts:26`), and `printf 'a\` plus a newline and `b'` becomes `printf 'ab'`. · Do not rewrite the text. Let the anchored rules cross a continuation instead: replace `UNTIL` with `(?:[^\n;|&]|\\\r?\n)*?` and allow `\\\r?\n` in the gap before the flag value, so only redaction changes and every other character reaches the judge as written. Add the `echo x \\` row and the heredoc row, each expecting the input unchanged.
