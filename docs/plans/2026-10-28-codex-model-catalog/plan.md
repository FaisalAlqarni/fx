# Codex model catalog and Codex render: implementation plan

> **Build this with `fx-implement`. Do not execute the tasks directly.**
>
> The tasks below are deliberately detailed. That makes them easy to follow and
> it is exactly why the lane gets skipped: nothing looks missing. What is
> missing is everything a task file cannot hold, and it is what `fx-implement`
> supplies: a worktree so the main checkout is never written to, a ledger that
> survives compaction, a fresh subagent per task, a review while each diff is
> still small, and lens dispatch on what the diff actually touched.
>
> Steps use `- [ ]` checkboxes.

**Design:** `./design.md`
**Goal:** On Codex, fx declares a third-party model to Codex through a profile-scoped `model_catalog_json` entry, and renders the preamble for how Codex loads a lane.
**Architecture:** One new module, `src/lib/codex-catalog.ts`, holds a pure catalog builder plus a writer and a thin CLI (`node lib/codex-catalog.js setup [slug...]`); fx-setup and the conformance runner both call that CLI path. `PREAMBLE.md` gains one `{{ORDER}}` slot; only the Codex render changes, and it names absolute lane paths computed from the plugin root. A new ADR 0065 and `references/harnesses/codex.md` record the facts and the stated limit.
**Stack:** TypeScript compiled by `scripts/build` (esbuild, one file per source, outputs committed), Node 20 `assert` tests run as plain `node`, bash conformance runner with a bwrap jail, Codex CLI 0.164.0.
**Complexity:** Medium
**Risks:**
- HIGH: the profile replaces the whole model list for that profile: the report says so, and fx never edits `config.toml`.
- MEDIUM: Codex rejects fx's top-level marker key in the catalog JSON: task 02 proves the generated files against the real `codex --profile ... debug models` (no model call) before anything relies on them, and names the fallback if it fails.
- MEDIUM: an unknown slug needs Codex's fallback instructions, which no Codex command prints: task 01 vendors them from `rust-v0.164.0` with every non-ASCII character escaped.
- MEDIUM: a golden or equivalence fixture for Claude Code or opencode changes by a byte: task 03 re-records Codex fixtures only and checks `git diff --stat` shows no other render fixture.
- MEDIUM: `skills/fx-setup/SKILL.md` is 18,719 bytes against a 20,000 byte ceiling: task 04 adds at most about 1,200 bytes.
**Testing:** Unit: `lib/codex-catalog.test.js`, `lib/preamble.test.js`, `lib/preamble-equivalence.test.js` · Integration: `tests/gates/fx-setup-root-check.test.js`, `tests/conformance/openrouter.test.js`, `tests/conformance/live-openrouter.test.sh` with a stub `codex` · E2E: the paid proof protocol in design.md, run by the controller after the exit gate, not by a task.

## Global Constraints

- Codex CLI 0.164.0 is the measured version. The catalog's field set follows its `ModelInfo`. `apply_patch_tool_type` accepts `freeform` only.
- fx never writes or edits the user's `config.toml`. It writes only `$CODEX_HOME/fx-<provider>.config.toml` and its catalog file, and only when they are absent or carry fx's marker.
- Claude Code, opencode and opencode-v2 preamble renders stay byte-identical to 0.7.0.
- Nothing is added above the preamble's opening imperative (ADR 0002). The preamble is sent at SessionStart and SubagentStart only, never per turn.
- No new parsing of shell text for writes. ADR 0039's `apply_patch` match is the only shell write detection.
- The OpenRouter key crosses into a run only through `with-key.sh`, never as a variable or a file written outside live.sh's key file, and every live run ends with a key scan.
- No em dashes or en dashes in any text fx emits or ships.
- Sources are TypeScript under `src/`; the `.js` beside them is generated by `scripts/build` and committed with its source. `scripts/check-generated` fails on drift. Never hand-edit a generated file; `skills/fx-setup/SKILL.md` is generated from `commands/fx-setup.md` by `scripts/gen-command-skills`.
- Every new test file is added to `scripts/check-all` in the same task.
- Every `SKILL.md` stays under 20,000 bytes (`tests/gates/skill-size.test.js`).
- Tests and commands never touch the owner's home. Run them as `TMPDIR=/tmp/claude-1000/fx-codex/tests/tmp HOME=/tmp/claude-1000/fx-codex/tests/home npm_config_cache=/tmp/claude-1000/fx-codex/tests/npm scripts/scratch-env <command>`. Nothing is written or deleted under `/home/faisal`.
- Owner shell rules for anyone running commands: never type `rm`, `trap`, `bash -c` or `sh -c`; run Python only as `python3 -I`. Do not add new `rm`, `trap`, `bash -c` or `sh -c` text to shell scripts. TypeScript tests may clean their own temp dirs with `fs.rmSync` as existing tests do.
- Commit on branch `codex-catalog` only, staged by path. No attribution trailers. No push, no merge.
- Locale: not applicable. fx has no user interface locale; its text is English.
