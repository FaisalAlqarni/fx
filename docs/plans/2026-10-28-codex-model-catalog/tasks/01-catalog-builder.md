# 01: Catalog builder and Codex's fallback entry

**Status:** ready-for-agent
**Blocked by:** None: can start immediately
**Phase:** MVP

**What to build:** a pure function that turns the model entries Codex itself reports (the `models` array of `codex debug models`) plus a list of slugs into a Codex `model_catalog_json` document. For each slug it starts from Codex's own entry, keeps every field, and sets `include_skills_usage_instructions: true` and `apply_patch_tool_type: "freeform"`. A slug with no Codex entry gets a field-for-field clone of Codex 0.164's fallback `ModelInfo` and is listed in `cloned`. A slug whose entry already has a skill contract is refused. No file I/O beyond loading the vendored fallback; task 02 writes files.

**Design:** Implementation Decisions; Testing Decisions; Global Constraints

**The fallback file.** Codex 0.164 source is checked out read-only at `/tmp/claude-1000/sp-research/codex/codex-rs` (tag `rust-v0.164.0`). Build the JSON from `models-manager/src/model_info.rs` lines 98-155 (`model_info_from_slug`), serialised the way Codex serialises `ModelInfo` (`protocol/src/openai_models.rs` `pub struct ModelInfo`: fields with `skip_serializing_if = "Option::is_none"` are omitted when None; `supports_reasoning_summary_parameter` is omitted because it is true; `used_fallback_model_metadata` is never serialised). The field set that Codex 0.164 accepted live is the one in `/tmp/claude-1000/fx-codex/spike/mkcat.py`; use it as the cross-check. `slug` and `display_name` are the placeholder `""` (the builder fills them). `model_messages` is `{"instructions_template": <the exact text of models-manager/prompt.md>}`. prompt.md holds 9 em dashes: write every non-ASCII character as a `\uXXXX` JSON escape so the shipped file holds no literal em or en dash, and the parsed string still equals prompt.md exactly. Generate the file with a one-off `python3 -I` script kept outside the repository (for example under `/tmp/claude-1000/fx-codex/notes/`), using `json.dump(..., ensure_ascii=True, indent=1)`.

**Interfaces:**
- Produces:
  ```ts
  export interface CatalogResult {
    catalog: { fx_generated: string; models: Record<string, unknown>[] };
    cloned: string[];                       // slugs built from the fallback, in input order
    refused: { slug: string; reason: string }[];
  }
  export function buildCatalog(args: { entries: unknown[]; slugs: string[]; fallback?: Record<string, unknown> }): CatalogResult
  export function loadFallback(): Record<string, unknown>   // reads codex/fallback-model-info.json beside lib/
  export const CATALOG_MARKER: string     // the value of catalog.fx_generated
  ```
  `CATALOG_MARKER` is exactly `generated by fx (lib/codex-catalog.js); fx-setup rewrites this file`.
  `fallback` defaults to `loadFallback()`. Module export style follows `src/lib/plant-roles.ts` only if a plain `export function` does not compile to something `require()` can use; check how `src/lib/preamble.ts` exports and match it.

**Seam:** `buildCatalog`, the new seam (design Testing Decisions, seam 1). Assert on the returned document, never on how it was built.

**Tests:**
- Flags flipped, everything else kept: `entries` holds one entry `{ slug: 'anthropic/claude-haiku-4.5', display_name: 'Claude Haiku 4.5', context_window: 200000, max_context_window: 200000, include_skills_usage_instructions: false, apply_patch_tool_type: null, base_instructions: 'BASE', model_messages: { instructions_template: 'BASE' }, shell_type: 'unified_exec', visibility: 'list' }`, slugs `['anthropic/claude-haiku-4.5']`. `catalog.models` deep-equals `[{ ...thatEntry, include_skills_usage_instructions: true, apply_patch_tool_type: 'freeform' }]`; `context_window` is `200000`; `cloned` is `[]`; `refused` is `[]`; `catalog.fx_generated === CATALOG_MARKER`.
- The input is not mutated: after the call above, the entry object still has `include_skills_usage_instructions === false` and `apply_patch_tool_type === null`.
- Unknown slug gets the fallback clone: `entries: []`, slugs `['acme/m1']`. `catalog.models.length === 1`; that model's `slug === 'acme/m1'`, `display_name === 'acme/m1'`, `context_window === 272000`, `max_context_window === 272000`, `include_skills_usage_instructions === true`, `apply_patch_tool_type === 'freeform'`, `model_messages.instructions_template === loadFallback().model_messages.instructions_template`; `cloned` deep-equals `['acme/m1']`.
- Skills flag already on is refused: one entry with `include_skills_usage_instructions: true`, slug `'gpt-5.5'`. `catalog.models` is `[]`; `refused` deep-equals `[{ slug: 'gpt-5.5', reason: 'already has skill usage instructions' }]`.
- Own `# Skills` section is refused: one entry `{ slug: 'gpt-6.1-sol', include_skills_usage_instructions: false, model_messages: { instructions_template: 'You are Codex.\n\n# Skills\n\nUse skills when...' } }`. `refused` deep-equals `[{ slug: 'gpt-6.1-sol', reason: 'its instructions carry their own # Skills section' }]`. The same holds when the text is only in `base_instructions`.
- Duplicate slugs collapse: slugs `['acme/m1', 'acme/m1']` with `entries: []` gives `catalog.models.length === 1` and `cloned` deep-equals `['acme/m1']` (Codex rejects duplicate slugs in a catalog).
- Empty slug list is an error: `buildCatalog({ entries: [], slugs: [] })` throws an `Error` whose message is `no slugs: Codex rejects an empty model catalog`.
- The vendored fallback is Codex's: `loadFallback()` has `include_skills_usage_instructions === false`, `apply_patch_tool_type` absent or `null`, `context_window === 272000`, `shell_type === 'unified_exec'`, and `model_messages.instructions_template` starts with `You are a coding agent running in the Codex CLI`. The raw bytes of `codex/fallback-model-info.json` contain no U+2014 and no U+2013 character.

**Risks:** prompt.md's em dashes leaking into a shipped file trips `scripts/check-prose`; the `\u` escapes prevent that. Do not "fix" the dashes in the text: Codex sends this exact text.
