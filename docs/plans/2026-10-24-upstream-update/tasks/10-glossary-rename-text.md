# 10: Glossary rename in fx text and the migration script

**Status:** ready-for-agent
**Blocked by:** 08, 09
**Phase:** 2: Renames and rebase

**What to build:** every fx file that names the glossary says GLOSSARY.md and GLOSSARY-MAP.md, and every lane that reads it reads the old name when the new one is absent, never creating a GLOSSARY.md beside an existing CONTEXT.md. An owner's existing files are renamed only on a yes, by a small script that is tested on a scratch repository shaped like the owner's own (a root map that links one CONTEXT.md per engine):
- the script follows the map's links: it renames the root `CONTEXT-MAP.md` to `GLOSSARY-MAP.md`, every `CONTEXT.md` the map links to `GLOSSARY.md` in the same directory, and a root `CONTEXT.md` to `GLOSSARY.md`, each with `git mv`;
- it rewrites the map's links and the old names in `CLAUDE.md`, `AGENTS.md`, `repo.md` and `docs/**`, never in `docs/plans/` or `docs/adr/`;
- it prints the full list first (dry run) and changes nothing without `--apply`; it never overwrites an existing GLOSSARY file and commits nothing.
`/fx:fx-setup`, or the next lane that writes to the glossary in the owner's own session, shows the dry-run list and asks once; on yes it runs the script with `--apply`; on no it writes `"glossary_rename": "declined"` to `.fx.json` and never asks again. A dispatched subagent never asks: it writes to the old-named file. `references/vocab/domain-modeling.md` regains the map format with its Relationships section and "if unclear, ask" (`compare-1` D2).

**Interfaces:**
- Consumes: `.fx.json` key `glossary_rename` with value `"declined"` and `findGlossary(root)` (task 09), whose search order the prose rule states in the same order.
- Produces: `planMigration(root: string): { moves: { from: string; to: string }[]; edits: string[]; conflicts: string[] }`, paths relative to `root`, sorted; `conflicts` lists every `to` that already exists, and a non-empty `conflicts` makes `--apply` exit 1 without moving anything.
- Produces: `applyMigration(root: string): void`, which runs `git mv` for each move, then rewrites `CONTEXT-MAP.md` to `GLOSSARY-MAP.md` and `CONTEXT.md` to `GLOSSARY.md` in the map and in each file of `edits`.
- Produces: the command line `node lib/glossary-migrate.js <root>` prints one line per move, `git mv <from> <to>`, then one line per edit, `edit <file>`, then `dry run: nothing changed`, and exits 0; with `--apply` it applies and prints `moved <n>, edited <m>, committed nothing`.

**Seam:** `planMigration` and `applyMigration` on a scratch git repository; the text gates; `tests/gates/user-invoked.test.js` for the regenerated fx-setup skill.

**Tests:**
- Multi-context plan: scratch git repo with `CONTEXT-MAP.md` containing `[a](engines/a/CONTEXT.md)`, `engines/a/CONTEXT.md`, root `CONTEXT.md`, `CLAUDE.md` containing `See CONTEXT-MAP.md.`, and `docs/plans/x.md` containing `CONTEXT.md`; `planMigration(repo)` returns `moves` exactly `[{from:'CONTEXT-MAP.md',to:'GLOSSARY-MAP.md'},{from:'CONTEXT.md',to:'GLOSSARY.md'},{from:'engines/a/CONTEXT.md',to:'engines/a/GLOSSARY.md'}]`, `edits` exactly `['CLAUDE.md']`, `conflicts` `[]`.
- Dry run changes nothing: the command line without `--apply` prints exactly `git mv CONTEXT-MAP.md GLOSSARY-MAP.md`, `git mv CONTEXT.md GLOSSARY.md`, `git mv engines/a/CONTEXT.md engines/a/GLOSSARY.md`, `edit CLAUDE.md`, `dry run: nothing changed`; `git status --porcelain` is empty afterwards.
- Apply: with `--apply`, `GLOSSARY-MAP.md` contains `[a](engines/a/GLOSSARY.md)`, `engines/a/GLOSSARY.md` exists and `engines/a/CONTEXT.md` does not, `CLAUDE.md` contains `See GLOSSARY-MAP.md.`, `docs/plans/x.md` still contains `CONTEXT.md`, stdout ends `moved 3, edited 1, committed nothing`, and `git log` has the same commit count as before.
- Conflict: the same repo plus an existing `engines/a/GLOSSARY.md`; `--apply` exits 1, `conflicts` is `['engines/a/GLOSSARY.md']`, and no file moved.
- `node tests/gates/user-invoked.test.js`: OK after `python3 -I scripts/gen-command-skills`; before regenerating it fails with `fx-setup: skill body has drifted from the command body`.
- `grep -rln "CONTEXT.md\|CONTEXT-MAP" skills references commands README.md INSTALL.md`: exactly these files: `references/vocab/domain-modeling.md`, `commands/fx-setup.md`, `skills/fx-setup/SKILL.md`, `README.md`, `INSTALL.md`, and the five COVERAGE files listed above.
- `node tests/gates/skill-size.test.js`: `skill-size: OK`; fx-tdd SKILL.md under 18,750 bytes, fx-brainstorm under 17,650.

**Risks:** `domain-modeling.md` is a reference and must not name another reference file in backticks. The lanes point at `domain-modeling.md` for the old name instead of naming CONTEXT.md themselves, which is what keeps the grep list above exact. The scratch repository lives under `os.tmpdir()`; the test commits with `-c user.name=fx -c user.email=fx@example.invalid` and leaves the directory in place.

**Idempotency:** `applyMigration` on an already migrated repo finds no CONTEXT files, plans no moves and exits 0 with `moved 0, edited 0, committed nothing`; it never overwrites a GLOSSARY file.

**Testing:** unit against a real git repository; text gates and the generated-skill drift check.
