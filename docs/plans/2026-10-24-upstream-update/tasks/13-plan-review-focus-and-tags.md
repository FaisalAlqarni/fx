# 13: Plan Review Focus, framing and red-team tags

**Status:** ready-for-agent
**Blocked by:** 01, 12
**Phase:** 3: Lane improvements

**What to build:** a plan names the inputs and failure modes its design implies but no task tests, pins each to a test in the owning task, and every reviewer receives that list beside Global Constraints. In fx-plan (`compare-2` P1 to P3, P11, P12, TR5):
- the plan.md template gains `## Review Focus` after Global Constraints: up to five lines, each the input or condition, the behaviour a reasonable user expects, and the owning task; empty means checked and none found;
- self-review gains check 5, Review Focus (for each input or failure the design implies, name the task whose Tests cover it; the rest go into Review Focus and into the owning task's Tests), and check 6, proportion (a plan several times the design's length is a transcript: cut it back to decisions);
- "Who you are writing for" ends with "What they cannot know is what you decided: which files, which names and signatures, which values from the design, which tests prove each task. Write those.";
- section 4 forbids scratch builds: "Read, do not build: no scratch implementation and no trial runs while planning. A question only running code can settle goes to `prototype`.";
- the task template gains an optional `**Not this task:** <adjacent behaviour> (task NN)` line, and Quality red flags gain "A requirement split across tasks names the owner of each half in both tasks.";
- red-team findings in plan mode end `[blocks]` or `[advisory]`; an unattended revision applies only `[blocks]` and ledgers each `[advisory]` finding to `state.md` without editing the plan.
`compile-brief` copies the Review Focus body into every brief, and the final branch review brief carries it verbatim (F23).
