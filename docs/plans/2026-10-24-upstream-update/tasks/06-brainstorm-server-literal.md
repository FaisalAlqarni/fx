# 06: Brainstorm page server inserts content literally

**Status:** ready-for-agent
**Blocked by:** 01
**Phase:** 1: Room and fixes

**What to build:** a mockup shown through the brainstorm visual companion arrives in the browser with exactly the text the owner gave, including `$&`, `$'` and `` $` ``. Today `src/skills/fx-brainstorm/scripts/server.cts` builds the page with `frame.replace('<!-- CONTENT -->', content)`, and `String.prototype.replace` with a string replacement expands those sequences, so a price like `$'` or a regex holding `$&` is silently rewritten. Insert the content with a replacer function, as superpowers 7.0.0 did.

**Design:** Phase 1: Fixes; Testing Decisions

**Files:**
- Modify: `src/skills/fx-brainstorm/scripts/server.cts` (the `replace('<!-- CONTENT -->', ...)` call, line 251 at dd99986)
- Modify: `skills/fx-brainstorm/scripts/server.cjs` (generated by `scripts/build`)
- Test: `src/tests/gates/brainstorm-server.test.ts`, built to `tests/gates/brainstorm-server.test.js`

**Seam:** the real server, started by `brainstorm-server.test.js` on a scratch directory and asked over HTTP on 127.0.0.1, as the existing cases do.

**Tests:**
- Special replacement patterns survive: write a content file `literal.html` whose body is `` <p id="lit">price $' and match $& and pre $` here</p> `` into the session's content directory, fetch the served page with the session key; the response body contains exactly `` <p id="lit">price $' and match $& and pre $` here</p> `` and contains the frame markup once.
- The existing cases (bootstrap page, cookie route, refusal without a key with status 403, screen-added event, shutdown with the owner) still pass.

**Testing:** integration over real HTTP, offline.
