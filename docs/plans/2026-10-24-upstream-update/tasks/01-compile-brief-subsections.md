# 01: compile-brief resolves subsection headings; version 0.6.0

**Status:** ready-for-agent
**Blocked by:** None: can start immediately
**Phase:** 1: Room and fixes

**What to build:** every later task in this plan names `### Phase N: ...` headings of design.md in its `**Design:**` line. Today `compile-brief` matches only `## ` headings and dies on those. After this task a Design or Stack entry may name a heading at any level from `##` to `######`, and the excerpt runs to the next heading of the same or a higher level, so a `##` section still carries its `###` children. The same task raises the plugin version to 0.6.0, because `tests/gates/release-version.test.js` fails every branch that changes a shipped file without a version above main's 0.5.0, and it runs last in every `test_scope`.

**Design:** Testing Decisions

**Files:**
- Modify: `src/skills/fx-implement/scripts/compile-brief.ts` (the `section` function)
- Modify: `skills/fx-implement/scripts/compile-brief` (generated by `scripts/build`)
- Test: `src/skills/fx-implement/scripts/compile-brief.test.ts`, built to `skills/fx-implement/scripts/compile-brief.test.js`
- Modify: `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`, `package.json`, `package-lock.json` (both `"version"` fields): 0.5.0 to 0.6.0

**Interfaces:**
- Produces: `section(md: string, heading: string): string | null` matches a line `^#{2,6}\s+<heading>$` (case-insensitive, trimmed) and returns that line through the line before the next heading whose level is the same or higher. Every later task's Design line depends on it.

**Seam:** the built `compile-brief` binary, run by `compile-brief.test.js` against a scratch plan directory, asserting the brief file it writes.

**Tests:**
- Subsection entry: design.md `# D\n\n## Implementation Decisions\n\n### Phase 1: Size gate\n\nG body.\n\n### Phase 1: Skill splits\n\nS body.\n\n## Out of Scope\n\nO1.\n`, task `**Design:** Phase 1: Size gate`; exit 0, the brief's `## Design excerpt` contains `### Phase 1: Size gate` and `G body.` and does not contain `S body.` or `O1.`.
- Parent entry keeps its children: same design, task `**Design:** Implementation Decisions`; exit 0, the excerpt contains `G body.` and `S body.` and not `O1.`.
- Unknown subsection: task `**Design:** Phase 9: Missing`; exit 2, stderr exactly `compile-brief: Design entry resolves to nothing: Phase 9: Missing`.
- The existing assertions in `compile-brief.test.ts` (six sections in order, `Implementation Decisions > 2`, stack entry `rails/The traps`) still pass unchanged.

**Testing:** unit, through the built binary; then `test_scope` on the source and test paths.
