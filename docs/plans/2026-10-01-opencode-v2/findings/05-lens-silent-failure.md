Lens: silent-failure, 4 findings

1. [Critical] `/development/fx/.worktrees/opencode-v2/plugins/fx-opencode-v2.js:124`: the whole guard is registered inside `attempt('permission.evaluate', () => ctx.permission.hook(...))`. If `ctx.permission.hook` throws or rejects at registration, for example because the hook name or shape changed in a newer opencode, `attempt` writes one `console.error` line and `setup` carries on. No evaluate hook exists after that, so every shell command is allowed. The deny paths at lines 128-142 never run, because the code that would run them was never installed. The plugin reports success and nothing in the session says the git guard is off. That covers force-push, `reset --hard` and pushes to the base branch. The try/catch inside the hook only fail-closes errors raised while a hook is running. It does not cover a hook that never registered. The task-04 finding 3 covers this registration hole only for the hidden-lane backstop. It does not mention that the git guard shares the same registration.

[Important] `/development/fx/.worktrees/opencode-v2/plugins/fx-opencode-v2.js:117`: `commands.set(ev.id, String(ev.input.command))` turns a missing or differently shaped `command` field into the string `"undefined"`, or `"git,push,..."` for an array. The entry is recorded, so the `command === undefined` deny at line 130 never fires. `inspect` (`/development/fx/.worktrees/opencode-v2/lib/git-guard.js:225`) sees no `\bgit\b` in `"undefined"` and returns `{ allow: true }`. An error here (wrong input shape, renamed field) ends in allow, where an unrecorded entry would have ended in deny. Nothing is logged. A shell tool whose input does not carry `command` under that name defeats the guard silently.
