Adversarial review (code mode) `.fx/opencode-v2/review/2c0e8d2..0208fad.diff`

1. **A v2 install probably stops opencode 1.x from starting, or runs it without the guard.** The v2 install writes agent files with a `permissions:` field into the shared `agents/` folder (`render_opencode_v2_agent`, scripts/fx-opencode-install). design.md:108-111 says 1.18.25 refuses to load any agent that has `permissions`. It also points `plugins/fx.js` at the v2 module, which ADR-0036:5 says cannot run on 1.x. INSTALL.md:352-353 still says "the same directory still loads under 1.x". Task 06 step 7 only tested 1.x after re-running `--major 1`, never with the v2 install in place. ADR-0036:7 ("keep a 1.x install while trying 2.x") also contradicts design.md:117 ("one machine runs one major at a time"). Lens: integrity. Not in the ledger.

2. **Subagent provider-error detection only works on Codex.** `childProviderError` (tests/conformance/lib/openrouter.js) only reads Codex's `collab_tool_call` shapes. A 429 inside an opencode, opencode-v2 or Claude Code subagent comes back as "no error". The ledger ruling at state.md:175 says an error "anywhere" makes the run inconclusive, so the code covers less than the ruling. As a result, the "lens child wrote nothing" check in rows 12 and 18 can pass because the child died of a rate limit, not because fx stopped it. v2 rows 15, 17 and 18 ran after the free quota ran out (state.md:186). Lens: integrity, verification theater. Not covered by any review in the ledger.

3. **`check-all` cannot pass in one environment.** `conformance-free-opencode` and `conformance-free-opencode-v2` both use whichever `opencode` is first on PATH. v1 row 09 fails on 2.x (state.md:32). On 1.x, v2's `oc2_setup` exits 1 rather than reporting a GAP. Task 15's "ALL GREEN" came from two different PATHs (state.md:206). The final gate is therefore pieced together, not a single run. Fix: one binary variable per harness, or a wrong-major GAP. Lens: integrity, verification theater. The ledger records this as an observation, not a ruling.

4. **The installed policies (guard layer 2) are never checked against the real binary.** Rows 06 to 08 now use `git -C .` specifically to avoid the policies. The policies gate uses a copied wildcard matcher (its gaps are a deferred minor). tests/install/run.sh only checks the JSON shape. Probe Q5 proved one `shell:git push *` pattern. If the shipped set has a resource-format or wildcard mismatch, layer 2 is silently inactive or over-blocks, and nothing goes red. Lens: integrity, verification theater.

5. **The policies cannot be overridden and have no removal path.** The installer now writes deny rules into the user's global `opencode.json`. They block the user's own git commands in every project with "Blocked by configuration policy", which never mentions fx. Deleting the plugin link leaves them in place. The only ways out are a `--major 1` run or editing the file by hand, and INSTALL.md has no removal section. Before this branch the installer only wrote a harmless depth key. Lens: human-debuggability, maintainability. I am not reopening ADR-0037's decision that policies cannot be overridden. This finding is only about the missing exit.

6. **v2 command delivery is never exercised.** On v2, row 14 only lists the commands (`command.list`). fx's own `execute` (the `$ARGUMENTS` substitution, then `ctx.session.prompt`) has only stub-gate coverage. Probe Q8 tested a probe plugin, not fx's plugin. So "hidden from the model, still reachable by the user" is proven on v2 only up to the menu entry. Lens: integrity, verification theater.

7. **Row 15's v2 comment is out of date.** rows/15-subagent-dispatches-subagent.sh says v2 "passes only when the plugin let general dispatch". Since ruling 199, the grant comes from the runner's own scratch config (openrouter.js, merge-opencode-provider.js), so a pass proves that config works, not fx. Lens: readability, debuggability. The ruling itself stands; only the comment misleads.

Settled items I did not raise: the Q11 user-agent limit, the `echo | sh` gap, the dropped `general` grant, Codex `$fx:` addressing, the paid-listing qwen re-run, and the minors the ledger defers.
