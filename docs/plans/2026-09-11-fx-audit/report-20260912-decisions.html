Decisions only you can make

1. May HTML reports load scripts from CDNs?

The approved design says two things that cannot both hold. design.md:285-287 keeps reports small by loading Tailwind and Mermaid from CDNs. Its global constraint forbids any request to a third-party host from anything fx renders.

Today: the audit's own report fetches nothing. skills/fx-architecture/HTML-REPORT.md:45-47 still loads two CDN scripts, and reports are now committed, so anyone who opens one later makes those requests. Ruling AC.

2. Rename the command files, or keep the longer names?

Claude Code names a plugin command after its file, so every fx command resolves as /fx:fx-<name>. The README had always promised /fx:<name>, which returns "Unknown command".

Evidence: the slash_commands list in every probe session's init event; "Unknown command: /fx:audit" in two probe logs. Every document now states the names that resolve. Renaming the files changes what you type for four existing commands. Ruling AD.

3. Keep the audit as a skill, and what to do on opencode

A plugin command is never told where its plugin lives, so the first audit command searched the whole filesystem for its templates, reading settings and process information on the way. A skill is told its base directory, so the audit became a skill only you can invoke. It still types as /fx:fx-audit and costs nothing per turn.

On opencode, the installer links skills wholesale and builds commands only from commands/. So there the audit has no typed command, and the model may be able to select it. Options: change the installer, which ends "git pull updates skills"; revert the skill, which brings back the filesystem search; or accept it. Rulings AF and AG. Nothing on opencode could be tested here.

4. Add a dedicated pass for queue behaviour inside an audit?

The measurement narrowed the pipeline lens to one defect: work added to a queue with nothing checking the backlog. The other queue defects, such as head-of-line blocking, redelivery, poison messages, lease timing and retry jitter, are left to the reviewers branch review runs. An audit runs neither of those.

The audit now says plainly that it judges those only as far as its own reading reaches. Ruling AA; measurement in measurement-task05.md, provisional because the control omitted the broad reviewer.

5. Remove the companion's exclude-file step?

The companion now writes .fx/.gitignore containing *, which keeps the session key ignored even before git init. Its older step, which appends .fx/ to the repository's local exclude file, is now redundant and can refuse a safe start when .git cannot be written.

It fails closed and never exposes the key; the re-review ran the unwritable case. Removing it also stops the companion writing to your repository's exclude file, which no design story states. Ruling AK.

6. When to bump the plugin version

The plugin is still at 0.1.6. Installs are cached by version, so existing users get nothing from this branch until it changes. Every earlier release commit bumped it.

7. Remove the leftover test fixtures?

66 /tmp/fx-fixture-* directories remain from runs before the fix, some possibly from other jobs. Nothing adds to them now; the exit gate's check-all left the count unchanged. They are removed only with your say-so.

Not delivered, and not claimed to be: design stories 18 to 22 are superseded by the measurement. The lens has never been dispatched by its name, and Phases 3 and 4 of the audit have never run live.
