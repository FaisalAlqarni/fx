Architecture review for fx

Requirement: "to increase the speed and reduce the token usage. whenever i use brainstormin>desing>plan>impelemnt it takes soooooooo looooong to fininsh"

Scale it runs at: one owner, plans of 5 to 28 tasks; subagents carry 75% of tokens and 89% of turns; 99.4% of tokens are cache reads, so context per turn and turn count are the levers (01-current.md, explore/01-real-cost.md).

Assumed: review quality per task stays at today's bar; no CONTEXT.md exists, so terms are the code's own (lane, controller, implementer, ledger, lens, tripwire).

Problem: each implementer assembles 55 to 70 KB from separate modules that restate TDD three times and re-read the whole design.

Solution: the controller compiles one brief per task and the implementer reads that plus fx-tdd, nothing else.

  • leverage: one brief, every dispatch
  • locality: TDD rules in fx-tdd
  • design.md read once, by the controller
  • gate test pins brief size ceiling

Problem: every task spawns a 3 to 5 agent chain, and task files run 4 to 5 times the design because test code is written out in full.

Solution: a task states behaviour and names its tests, related slices merge until each task sits on one seam, and red-team fires on risk instead of task count.

  • leverage: fewer chains per plan
  • task file shrinks to behaviour
  • tests written at the interface
  • red-team stops firing on every plan

  participant P as plan
  B->>U: interview rounds (R)
  B->>U: confidence + approaches, one message
  B->>U: design.md, one approval

Problem: the design passes through the owner piece by piece in chat and then again as a file, and fx-plan re-confirms what was just approved.

Solution: brainstorm writes design.md once and gets one approval on the file; fx-plan skips the restate when the design was approved in this session.

  • owner stops drop from R+11 to R+3
  • design.md is the single interface
  • locality: approval lives in one place
  • gate tests pin the stop order
Contradicts ADR 0033 (the confidence check is its own stopping message), but worth reopening because it is one of the stops the requirement names, and the approaches can ride in the same message.

Problem: the branch pass re-reads code the tripwire lenses already reviewed, frontmatter model pins leak past route(), and the task reviewer reads the whole ledger for a few Ruling lines.

Solution: route() owns every model choice, the branch pass has a hard agent cap and skips lenses that already ran per task, and the task reviewer receives the rulings instead of the ledger.

  • locality: model choice in route()
  • delete two frontmatter pins
  • reviewer context drops by the ledger
  • dispatch-route tests cover fx: agents
Contradicts ADR 0029 (every lens runs at the branch pass), but worth reopening because a lens that fired on its tripwire per task reads the same diff again at the end.

Top recommendation

Compile one brief per implementer dispatch

Implementers are the largest share of the 75% of tokens that subagents spend, and a smaller brief cuts the cost of every dispatch on every plan, whatever the task count.
